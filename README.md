# VLA-4D

大创项目：复现 OpenVLA，并沿 4D 时空方向做改进。

**当前进度**：OpenVLA 四 suite 复现完成 → 单帧 token 消融完成（拿到核心发现）
→ 自建微调配方续训至 30 000 步达 **80.0%**，与官方 84.2% 的差距**不再显著**
→ **正在做 4D 池化主线**。
详见 [进度](#进度) 与 `docs/06-后续计划.md`。

## 核心发现

> **位置编码的影响比 token 压缩本身大五倍。**

把 OpenVLA 的 256 个视觉 token 压到 96 个（2.7×）：

| 做法 | LIBERO-Spatial 成功率 |
|---|---|
| 不压缩（基线，n=200） | 82.5% |
| 压到 96，**不修正位置** | **18.0%** |
| 压到 96，**修正 `position_ids`** | **72.5%** |

同一个压缩率、同一个算子，只改位置编码就差 **54 个百分点**；
而压缩本身的代价是 **−10.6 个百分点**（四 suite 合并，p=1.6e-03）。

原因在 `modeling_prismatic.py:381`：视觉块夹在 BOS 与语言 token 之间，
且 `position_ids=None` 让 Llama 按 `arange` 生成位置。压短视觉块，
**整个语言指令与动作解码位置都被前移**。把每个合并 token 的位置还原成
其成分 patch 的质心后，掉点几乎全部消失。

这直接支撑本项目的论点：**位置编码必须来自真实时空坐标，而非序列下标**——
也就是要做的 4D RoPE。完整实验与统计见 `docs/05-实验记录.md` §7。

## 快速开始

### 1. 环境（在租用的 GPU 服务器上）

```bash
git clone https://github.com/Quinn-0109/vla-4d.git && cd vla-4d
bash setup/setup_server.sh          # 自动探测数据盘；也可 DATA_DIR=/root/autodl-tmp 指定
source ~/.bashrc
```

脚本会装 conda 环境 / OpenVLA / LIBERO，按 `setup/constraints.txt` 锁定版本，
**把 conda 与 HuggingFace 缓存都放到数据盘**（系统盘通常只有 30 GB，不重定向必爆），
最后自检 LIBERO 能否启动。

**💡 省钱：先用「无卡模式」装环境和下模型。** 装环境 + 下 checkpoint 要 5–8 小时，
无卡模式下几乎不花钱，装完再切 GPU 模式。

```bash
bash setup/setup_server.sh
bash scripts/download_checkpoints.sh libero_spatial   # 约 15 GB
bash setup/check_gpu.sh                               # 切回 GPU 模式后自检
```

> ⚠️ **新开终端/tmux 窗口会掉回 base 环境**（conda init 的行为），
> 这个坑本项目踩过四次。建议把 `conda activate <环境路径>` 和
> `cd <仓库路径>` 加进 `~/.bashrc`。各启动脚本已加前置检查，
> 环境不对会直接拒绝而不是给出误导性的报错。

### 2. 熟悉 LIBERO（不加载模型，几分钟）

```bash
python scripts/explore_libero.py list      # 列出 5 个 suite 的全部任务
python scripts/explore_libero.py inspect   # 观测字典结构 + 动作空间含义
python scripts/explore_libero.py probe     # 逐维施加动作，看末端怎么响应
```

配合 `docs/03-LIBERO使用指南.md`。**纯评测不需要下载 LIBERO 数据集**
（初始状态与环境定义随仓库自带，省 10 GB+），理由见指南第 5 节。

### 3. 评测

```bash
bash scripts/run_eval.sh smoke              # 冒烟测试，先确认跑得通
bash scripts/run_eval.sh full               # 4 suite × 50 trials
python src/analysis/analyze.py --traj_dir results/trajectories
```

### 4. token 消融

```bash
bash scripts/run_token_ablation.sh cost     # 先看耗时与费用估算
bash scripts/run_token_ablation.sh budget   # 扫 token 预算找拐点
bash scripts/run_token_ablation.sh diag     # 分离「信息损失」与「位置错位」
bash scripts/run_token_ablation.sh fixpos   # 位置修正
python src/analysis/collect_ablation.py --suite all   # 跨 suite 合并检验
```

### 5. 多帧微调（阶段 B）

```bash
python scripts/probe_vram.py --sweep        # 显存实测，定 K 与 batch
bash scripts/prepare_finetune.sh check      # 体检: 环境/磁盘/依赖版本
bash scripts/prepare_finetune.sh data       # 下 RLDS 数据集（每 suite 约 1.9 GB）
python scripts/finetune_single.py --bench_only True   # 先测吞吐再决定步数
python scripts/merge_lora.py --adapter runs/<exp>/adapter/step10000 --out <出口>
```

## 硬件要求

### 架构门槛：Ampere (sm80) 及以上

官方 `openvla_utils.py:45` 默认 `attn_implementation="flash_attention_2"`，
配合 `torch_dtype=torch.bfloat16`。**若 flash-attn 装不上，
`setup_server.sh` 的 `SKIP_FLASH_ATTN=1` 会把它改成 sdpa**——
二者是同一注意力运算的不同 kernel，数值近乎一致，成功率不受影响
（论证见 `docs/05` §1 偏离①）。但 bf16 仍要求 Ampere 及以上。

| | GPU | 算力 |
|---|---|---|
| ❌ 跑不了 | V100 / T4 / RTX 2080Ti | 7.0 / 7.5 |
| ✅ 可用 | A100(8.0)、A10·A5000·A6000·RTX 3090(8.6)、RTX 4090·L20·L40S(8.9)、H100(9.0) | ≥8.0 |

### 显存（RTX 4090 24 GB 实测，非估算）

权重本身占 **15.13 GB**，余下约 8.6 GB 全部留给激活。
全表 `results/tables/vram_probe_frozen.md`
（`python scripts/probe_vram.py --sweep --freeze_vision`，**冻结视觉主干，与实际训练一致**）。

| 用途 | 峰值 | 备注 |
|---|---|---|
| 评测（bf16） | 15.4 GB | RTX 4090 约 6 Hz |
| 单帧 LoRA 微调 | **16.8 GB** | b=4 + 累积 4 + 梯度检查点；实测锚点，探测值 16.66 |
| K=8 多帧微调（不压缩，256/帧） | **17.4 GB** | 开梯度检查点。不开则 K 最多到 4 |
| K=8 多帧微调（压到 96/帧） | 16.3 GB | 与不压缩只差 1.1 GB |
| K=16 多帧微调（不压缩） | **19.2 GB** | 同样只需开检查点，24 GB 卡够用 |

**三个反直觉的实测结论**：

1. **梯度检查点才是主要杠杆，不是压缩。** K=8 时压缩与否只差 1.1 GB——
   检查点已消掉大半 LLM 激活。压缩换来的是速度，不是显存。
2. **多帧根本不贵，贵的是那 15.13 GB 权重。** 开检查点后每加一帧只多
   0.20–0.23 GB，K=1→16 一共才涨 2.6 GB。**显存不是本项目选 K 的约束**，
   时间才是（见 `docs/06` §4.4）。
3. **上一版表的"token 更少反而更费显存"是配置错误的产物。** 那张表把 LoRA
   挂在了视觉主干上，于是 K 帧各自的 DINOv2+SigLIP 激活都要留着反传，
   与压缩无关地随 K 线性涨。冻结之后这个反常消失：显存重新随总 token 数
   单调（K=2×256=512 tok → 19.2 GB，K=4×96=384 tok → 18.4 GB）。
   结论"**多帧微调时冻结视觉主干**"仍然成立，但理由是**它就是官方配方**，
   不是"为了塞下 K=8 的被迫取舍"。

### 磁盘

| 项目 | 大小 |
|---|---|
| conda + PyTorch + CUDA 库 | ~18 GB |
| 单个 checkpoint (7B bf16) | ~15 GB |
| LIBERO RLDS 数据集 | **每 suite 约 1.9 GB**，四个 ~8 GB |
| LoRA adapter | 几百 MB（合并后才是 15 GB） |

⚠️ HuggingFace 默认缓存在 `~/.cache`（系统盘）。setup 脚本会重定向 `HF_HOME`
到数据盘；手动装务必自己设，否则 30 GB 系统盘必爆。

> **LIBERO 是同步仿真器**：`env.step()` 会等动作算完才推进，所以推理快慢
> **完全不影响成功率**，只影响评测要跑多久。选卡是花钱买时间，不是买正确性。

## 进度

### ✅ 阶段 0：OpenVLA 复现（四 suite 各 n=500）

| Suite | 本次复现 | 论文 | 差异 | p |
|---|---|---|---|---|
| Spatial | 84.2% | 84.7 ± 0.9 | −0.5 | 0.788 ✅ |
| **Object** | **84.0%** | 88.4 ± 0.8 | **−4.4** | **0.016** ❌ |
| Goal | 76.4% | 79.2 ± 1.0 | −2.8 | 0.192 ✅ |
| Long | 52.0% | 53.7 ± 1.3 | −1.7 | 0.511 ✅ |
| **平均** | **74.1%** | 76.5 ± 0.6 | −2.35 | 0.034 |

偏差几乎完全由 Object 一个 suite 驱动（若 Object 达论文值，平均差异降至
−1.25，p=0.260 不再显著）——**不存在系统性复现偏差**。

**另一项发现：LIBERO 评测是完全确定性的。** 换种子复跑逐位相同
（`env.seed(0)` 硬编码 + 初始状态读自文件 + 贪心解码）。
推论：论文的 ±0.9% 只可能来自 3 次独立微调，而非评测种子；
仅拿到一份 checkpoint 的复现者**在原理上无法触及训练种子方差**。见 `docs/05` §3.2。

### ✅ 阶段 1：单帧 token 消融

见上文[核心发现](#核心发现)。附带产出：

- **冗余度量**：特征空间 top-10% 的 patch 承载 70–76% 的变化（`docs/04` §4.4）
- **信息底线**：4× 信息压缩几乎无损，8× 则崩溃——边界在 64 与 32 token 之间

### 🔶 阶段 2：自建微调配方（续训到 30 000 步后，差距不再显著）

| checkpoint | 满量成功率 | vs 官方 84.2% | p |
|---|---|---|---|
| step 20 000 | 74.0% | −10.2 | 7.3e-05 显著 |
| step 25 000 | 75.4% | −8.8 | 5.3e-04 显著 |
| **step 30 000** | **80.0%** | **−4.2** | **0.083 不显著** |

**曲线原本就没到平台**——20 000 步远未收敛。续训到 30 000 后差距从
−10.2 收到 −4.2，不再统计显著。

⚠️ **但不能说"追平"**：n=500 检出 4.2 点的功效只有 **41%**，
要 80% 功效需 n≈1307。正确表述是「在 n=500 下不再显著」，不是「等价」。

**五组训练步数定为 30 000**，理由是**质变在此发生**（25k vs 官方仍显著
p=5.3e-4，30k 不显著）——不是"30k 数字更高"（25k vs 30k 本身 p=0.081 不显著）。
一个**无法解释的显著缺口**会让审稿人直接判定实现有 bug，花 14.5 h 买掉它划算。

⚠️ **过程中翻过一次车**：曾以 n=50 子集判"硬门槛通过"（72.0% vs 76.0%, p=0.65），
满量推翻——那个 50 局子集恰好对官方 checkpoint 特别难
（官方子集 76.0% / 满量 84.2%，差 8.2 点；自建只差 2.0 点），
**不对称的难度偏差把真实差距掩盖了六个百分点**。

**这是 n=50 第三次误导本项目**（前两次：「2.7× 压缩免费」已撤回；
step15000 的 56% 被当成退化）。**子集是满量的严格子集，但不是无偏估计**——
确定性评测保证子集可复现，不保证它有代表性。今后判定一律用满量。

对主线的影响：**内部有效性保住了**（五组共用同一配方，残余偏移是共同的，
组内对比抵消），**外部有效性没有**（绝对数字不能与文献并列）。
缺口的两个候选与判别法见 `docs/05` §8.2 与 `docs/06` §4.4。

### 🔄 阶段 3：4D 池化主线（当前）

> **2026-08 路径重写。** 上一版铺了六项前置、五组对照、双相机、单目深度、
> 种子方差（~110 h），主线被淹没。现在是**五次训练**（~110 h，30 000 步/组由实测定，
> 含强命题所需的错配臂）。
>
> ⚠️ **总时长巧合地相同，但构成完全不同**：旧的 110 h 里散在双相机、单目深度、
> 种子方差、六项前置上；现在 **87 h 全是五组主线训练**，16 h 评测，7 h 前置。
> 同样的钱花在刀刃上，不是回退。砍掉的部分与捡回条件见 `docs/06` §6。

**要保护的那一句话**：

```
        池化用的坐标系 ＝ 位置编码用的坐标系

                Metric 4D Space
                      │
          ┌───────────┴───────────┐
          ↓                       ↓
     Patch Pooling            4D RoPE
          └───────────┬───────────┘
                      ↓
              同一套 (t, x, y, z)
```

**这比"4D RoPE"本身重要**——patch 级时空池化（STTM）、度量 3D 位置表征
（SpatialVLA / HiST-VLA）、3D 坐标做 RoPE（STRING）都各自有人做过，
**没人把这两件事放进同一个度量 4D 坐标系里耦合起来**。

**⚠️ 这是强命题，需要专门的实验撑。** "度量 4D 比图像网格好"只是弱命题;
"两者一致本身带来增益"才是框里那句。所以对照表里有**错配臂**：

**全部固定 token 预算 N=256**（= G0 的 token 数，于是每一组都在同一预算上）：

| 组 | 池化 | 池化坐标 | PE 坐标 | 角色 |
|---|---|---|---|---|
| G0 | — | — | 1D | 单帧基线 ✅ 74.0% (n=500) |
| G1 | 无（2048 tok） | — | 1D | 上限参考 |
| G2 | 帧独立→32/帧 | (h,w) | (t,h,w) | 粒度对照 **＋等预算历史对照** |
| G3 | patch 级跨帧 | (t,h,w) | (t,h,w) | 一致 |
| **G4** | patch 级跨帧 | **(t,x,y,z)** | **(t,x,y,z)** | **本方案**，一致 |
| **M2** | patch 级跨帧 | **(t,x,y,z)** | (t,h,w) | **错配臂** |

| 对照 | 隔离出什么 |
|---|---|
| **G2 vs G0** | **同预算下历史帧有没有用**（前提检验） |
| G3 vs G2 | 跨帧联合 vs 帧独立 —— 粒度 |
| **G4 vs G3** | 度量 4D vs 图像网格 —— **弱命题** |
| **G4 vs M2** | **一致 vs 错配 —— 强命题，标题句的唯一直接证据** |

⚠️ **前提检验用 G2 vs G0，不是 G1 vs G0**——后者差了 8 倍 token，
赢了说不清是历史帧有用还是单纯 token 多。

**G4 vs G3 与 G4 vs M2 都排在 11 月而不是最后**：留出转向时间。

**✅ 开跑前的证伪闸门已通过**（libero_10，n=20，6205 窗口）：

| 量 | 实测 | 判据 |
|---|---|---|
| 跨帧深度跳变率（同一 (h,w)、K 帧内 max−min > 5 cm） | **23.5%** | >15% ✅ |
| 跳变幅度 **> z 箱宽**（30.7 cm）的占比 | **19.2%** | >15% ✅ |

第二行是补测的：**发生率高不等于分得开**。判定"两个表面"用 5 cm，
而 z 轴 6 箱 / 1.84 m 跨度 = 箱宽 30.7 cm，差六倍——落在中间的跳变会被
分箱吃掉，G4≈G3 而不报任何错。实测衰减曲线很平（31.0% >1cm → 19.4% >30cm），
发生的跳变绝大多数是大幅度的，箱宽够用。

两条由此定下的限定：**z 轴主要分开前景与背景，不是物体级细结构**
（不能写成"能区分夹爪与其下方物体"）；**包围盒不敏感**（p5–p95 与 p5–p90
给出 19.2% vs 19.9%），所以 z 的 extent 不是可调超参。见 `docs/05` §8.6。

⚠️ **实现上先做最小版本，不要一上来把算子锁死**（`docs/06` §2.2）。
G3/G4 先用**零自由超参**的坐标空间分箱池化跑，两边同一份代码、只换坐标张量。
ToMe、新颖度打分、几何项 λ 全部压到 Phase 2——尤其 λ，
它在米和格子两个量纲里最优值必然不同，各自调优就等于给 G4 开小灶，
**核心对照会被一句话问废**。

⚠️ 另两条已知陷阱：**帧间隔从未定义**（K=8 取连续帧只有 0.4 秒"历史"，
跑出"历史没用"是必然的假阴性）；**评测必须 n=500**——期待效应量 10–15 点，
n=50 只能检出 25 点以上。

⚠️ novelty 必须精确表述：**"patch 级时空池化"（STTM, ICCV'25）与
"3D 坐标上做 RoPE"（STRING）都已经有人做了**。能站住的只有两者的**耦合**——
池化与位置编码共用同一套度量 4D 坐标系。见 `docs/04` §2.2。

## 我们额外记录的东西

官方评测脚本只输出 MP4 回放和成功/失败日志。`scripts/run_libero_eval_traj.py`
在保持评测逻辑一致的前提下，额外落盘每一步的动作、末端执行器位姿与夹爪状态，
由此可以算出官方没给的指标：

- 归一化 jerk、SPARC（轨迹平滑度）
- 速度方向反转次数、空转步数占比（抖动与停顿）
- 路径效率、动作抖动、夹爪翻转次数
- 完成时间 CT（对齐 VLA-4D 论文的指标）

## 技术路线

**底座选定 OpenVLA**（而非 Qwen2.5-VL）。理由：保住在 970k 条真实机器人轨迹上
预训练出的动作能力，且官方提供 4 个 LIBERO 微调 checkpoint 可直接对标。

原以为的代价是"要动 Llama-2 的 1D RoPE，改动深"。**这条已经消掉了**：
4D RoPE 采用**扩展式**而非替换式——保留 ~70% 通道原样跑 1D RoPE 完全不动，
另拨 ~30% 给 (t,x,y,z)，文本 token 在这些通道上取恒等旋转。
预训练通路不受影响，消融时把 4D 通道置恒等即天然退化成基线。`docs/04` §5.1

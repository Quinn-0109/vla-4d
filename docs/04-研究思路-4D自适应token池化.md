# 研究思路：4D 自适应 Token 池化

> 状态：底座已定为 **OpenVLA**（§6 岔路口已关闭），基线复现与单帧 token 消融已完成（见 `docs/05`）。
> **2026-08 文献复查两轮**：§2.5 精读最接近的两篇；**§2.2 收紧 novelty 表述**——
> "patch 级时空池化"与"3D 坐标做 RoPE"**都已有人做**，能站住的只有两者的**耦合**。
> 实验路径见 `docs/06`。

## 1. 出发点

VLA 要做时空推理就得吃历史序列，但**序列里每帧只有很小一块区域是动态的、我们关心的**，其余要么静止要么是无关背景。于是：

- **VLA-4D** 建了历史序列并做时间戳编码，但**对输入序列不做任何采样/池化** → token 数随 K 线性膨胀
- **4D-VLA** 做 **frame-wise sampling**（整帧丢弃）→ 粒度太粗，丢帧就丢了时间分辨率

我们的位置：**保留全部 K 帧（时间分辨率不损失），但在帧内做 patch 级池化（去掉空间冗余）。**

### 这个问题有多严重（算一下）

OpenVLA 在 224×224、patch 14 下每帧 **256 个视觉 token**，单帧推理已经只有 **6 Hz**（RTX 4090，论文 3.5 节）。
K=8 的朴素历史堆叠 → **2048 个视觉 token**。注意力是平方复杂度，KV cache 线性增长，实际帧率会掉到 1–2 Hz 以下，**根本没法做闭环控制**。

所以这不是"锦上添花的加速"，是**让 4D VLA 可用的前提条件**。

## 2. ⚠️ 先做 novelty 核查：这个方向已经很挤

必须先说清楚，否则会在答辩/投稿时被打。**"对 VLA 做 patch 级 token 压缩"已经有至少 5 篇：**

| 论文 | arXiv | 做法 |
|---|---|---|
| VLA-Cache | 2502.02175 | 缓存跨帧不变的背景 token |
| VLA-Pruner | 2511.16449 | **patch-wise** 双层剪枝：取语义显著 ∪ 动作显著，再去冗余 |
| Token Expand-Merge | 2512.09927 | 免训练 token 压缩 |
| VLA-IAP | 2603.22991 | 交互对齐的免训练视觉 token 剪枝 |
| TEAM-VLA | — | early pruning + mid-layer **action-guided soft bipartite merging** |

**但它们有一个共同的、可被我们利用的盲点：全部是 2D 图像空间上的"推理加速"叙事，没有一篇在度量 3D + 时间的 4D 空间里做池化。**

### 2.2 ⚠️ 2026-08 补充核查：上面那句话说得太满，必须收紧

又查了一轮，**"没有一篇"是错的**，且错在三个不同方向。这三条必须自己先写进
related work，不能等审稿人指出来：

| 已存在的工作 | 做了什么 | 与我们的差别 |
|---|---|---|
| **STTM** (2507.07990, ICCV'25) | 帧内四叉树粗到细合并 + 沿时间定向配对合并 | **patch 级时空池化已经有了**。但在 **2D 网格 + 时间**，免训练，Video LLM 非 VLA，且不管合并后 token 的位置语义 |
| **SpatialVLA** | 深度估计器 → 3D 位置编码注入 patch token | **VLA 里注入 3D 位置不新**。但单帧、**不池化** |
| **HiST-VLA** (2602.13329) | 2D patch 反投影到车体 3D 系，MLP 编码 3D 坐标 | 同上，且是**加性**编码非旋转；自动驾驶；**不池化** |
| **STRING** 系列 | 3D 坐标上的 RoPE，强调平移不变性；真机抓取 65%→74% | ⚠️ **"3D 坐标做 RoPE"在机器人上已经有人做了，效果还不错** |
| TTF-VLA (2508.19257) | 跨多帧观测融合 patch token | 融合而非按预算池化 |
| RoboStream (2603.12939) | 对象级时空融合 token + 度量几何 | **对象级**，非 patch 级 |

**所以绝不能说"我们把 RoPE 用到 3D/4D 坐标上"——一句话就被打掉。**

能站住的只有交集：**池化与位置编码共用同一套度量 4D 坐标系**——
合并后 token 的位置就是各成分的度量质心 `(x̄,ȳ,z̄,t̄)`，RoPE 直接吃它。
现有工作里这两件事是**分开的**：池化的（STTM）不管位置语义，
编码位置的（SpatialVLA / HiST-VLA / STRING）不池化。

而这个耦合不是硬拼——§3 的三条论证说明两者互相需要。

### 2.5 2026-08 文献复查：两篇最接近的工作已精读

半年内该方向又增至 10+ 篇。精读了其中最接近的两篇，**结论是方向仍可继续**，
但差异化必须精确表述。

#### ETA-VLA（arXiv 2603.25766, 2026-03）—— 不构成撞车

其 Temporal Fusion Module 确实在"压缩历史帧冗余"，但四点关键差异：

| 维度 | ETA-VLA | 本方案 |
|---|---|---|
| **领域** | **自动驾驶**（NAVSIM v2，六路相机轨迹预测） | 机器人操作 / LIBERO |
| **粒度** | 整帧加权平均：`V_fused = Σwᵢ·V_seq,ᵢ / Σwᵢ`，把 K 帧塌缩成 1 帧的 token 量 | **patch 级、按时间变化门控** |
| **空间** | 2D 图像空间，无深度 | **度量 3D 坐标 + 时间** |
| **位置编码** | **刻意 RoPE-free**（其 ILSA 用 RoPE-free Semantic Scoring，以避开距离偏置） | **4D 度量坐标 RoPE** |

> **最后一条可直接写入 related work**：ETA-VLA 之所以要绕开 RoPE，是因为在
> **2D 图像网格**上 RoPE 的距离偏置是噪声；而在**度量 3D 坐标**上，
> 这一距离偏置恰恰编码了真实几何关系——同一机制在不同坐标系下从缺陷变为特性。

其 TFM 的加权平均是很粗的手段：整帧平均会抹平每帧的空间细节，
恰好是本方案用 patch 级门控要避免的。

#### Drop-Then-Recovery（arXiv 2606.27755, 2026-06）—— 不同维度

标题"How Redundant Are VLA Models?"看似与本方案的冗余度量重合，实则不同：

| | Drop-Then-Recovery | 本方案 |
|---|---|---|
| 冗余维度 | **模型深度**——移除 transformer block 后微调，看能否恢复 | **输入 token**——历史帧中哪些 patch 是静态的 |
| 手段 | block removal + GateProbe 重要性排序 | patch 级时空池化 |

**patch 级的时空冗余分布仍无人测量。**

该文有一处发现对本方案有利：**LIBERO 上移除一半 LLM block，
OpenVLA-OFT 反而从 95.0% 提升到 98.3%**，说明语言骨干在操作任务上高度冗余，
模型容量更应分配给视觉与动作通路——支持"在视觉输入侧下功夫"的路线。

但这也构成一条警示：**既然模型冗余到砍一半层都不掉点，
"压缩视觉 token 而不掉点"本身就不是一个有说服力的结果。**

### 因此叙事必须重构

| | 不要这样说 ❌ | 要这样说 ✅ |
|---|---|---|
| 目标 | "我们让 VLA 推理更快" | "我们让 4D 历史表征更好" |
| 卖点 | token 少了 X%，速度快了 Y 倍 | 在同等 token 预算下，4D 池化比 2D 池化保留更多任务相关信息 |
| 对手 | VLA-Pruner / VLA-Cache（正面硬碰） | VLA-4D（不池化）与 4D-VLA（整帧采样）——我们在它们中间 |
| 核心消融 | 池化 vs 不池化 | **在 2D 池化 vs 在 4D 池化**（token 预算固定） |

效率是**副产品**，不是论点。这样既避开五篇效率论文的正面竞争，又接回大创立项的 4D 主线。

## 2.6 ⚠️ 一个必须先说清楚的边界：历史帧不修复特征质量

若视觉主干冻结、只把多帧特征合并送进 LLM，**视觉特征本身并没有变好**。
DINOv2+SigLIP 在第 t 帧分不清的东西，在 t−1…t−7 帧里同样分不清。
所以本项目**不主张**"多帧提升视觉判别力"。

历史帧提供的是**任何单帧都不包含的信息**——只能由变化观测的状态
（夹爪正在闭合还是张开）、被遮挡物体的记忆、多步任务的阶段消歧。
这与特征质量是正交的两个轴。

这条边界对写作是有利的：**贡献的归因变得干净**——任何收益都不能被
解释成"换了更好的编码器"，只能来自模型索引时空信息的方式。

验证这个前提的控制实验是 **G1 vs G0**（`docs/06` §3，主战场 LIBERO-Long，
因为 Spatial/Object/Goal 多为单步、基本全可观测的任务）。

## 3. 为什么"在 4D 上做"不是包装，是必要的

> ⚠️ **2026-08 重写。** 本节旧论证是「2D 剪枝隐含静态相机假设，腕部相机打破它」，
> **该论证在本设置下不成立**：OpenVLA 在 LIBERO 上按 Appendix E
> **只用第三人称静态相机**，静态相机下图像平面坐标跨帧本就可比。
>
> 旧的补救方案（加腕部相机 + 单目深度）代价过大——token 预算翻倍、K 上限重测、
> 基线重跑——且**只是为了救一条论证**。已弃用。
> 下面三条论证**在单个静态相机下就成立**，腕部相机降为可选扩展（`docs/06` §6）。

**完整表述见 `docs/06` §1.2。** 摘要：

**① 深度阻止错误合并（池化侧）。** 图像网格里同一 (h,w)、不同帧的两个 patch 会被
判为"同一位置"而合并。但机械臂不断从物体前面划过：t−5 帧那格是背景，t 帧是夹爪，
合出来的 token 不代表任何真实表面。度量坐标下 z 相差十几厘米，直接分开。
**遮挡/去遮挡在操作任务里高频发生，这是最实际的收益。**

**② 度量坐标与操作相关的空间关系更对齐（编码侧）。** 合并后 token 的位置是质心，
而 RoPE 的 `q·k` 只依赖位置之差——质心距离会直接进到注意力里。
图像网格下它是**像素距离**（随视角变化），度量坐标下是**厘米数**。

> ⚠️ **三条里最弱的一条，表述必须克制。** 能说的是"几何感知的关系表征，
> 与操作任务里真正起作用的空间关系**更对齐**"；**不能说**"RoPE 的距离就是
> 动作距离，所以一定更适合动作预测"——审稿人一句"视觉 token 的 3D 欧氏距离
> 凭什么等同于动作距离"就能问倒。且 **G4 vs G3 检验的是 ①③，证伪不了 ②**，
> 所以它只能作动机，不能作结论。详见 `docs/06` §1.2。

**③ 预算分配有了物理判据。** "离夹爪/目标近的 patch 重要"在度量空间说得出来；
图像网格里说不了——远处背景 patch 在像素上可以紧挨着夹爪。

**①③ 属于池化，② 属于编码，三条指向同一套坐标系。**
这就是"池化与位置编码必须共用度量 4D 坐标"的理由——它们不是拼在一起的两个模块，
是互相需要的。这才是论文的论点（`docs/06` §1.1）。

> **多相机去重是加分项，不是必需项**：若两路相机的 patch 都反投影到同一个世界系，
> 同一物理位置被两个相机看到的两个 token 可以合成一个——纯 2D 方法结构上做不到。
> 留作扩展消融，不进主线。

## 4. 池化怎么设计

### 4.1 总体：四阶段（⚠️ **候选设计，不是定案**）

> **2026-08：这一整套是 Phase 2，不是开工形态。** 要验证的命题只有一个——
> metric 4D pooling 是否优于 image-grid pooling。把新颖度打分、跨帧 ToMe、
> λ 几何项、size 加权质心全部同时上线，一旦 G4 ≈ G3 就分不清是坐标系没用
> 还是某个环节没调好。
>
> **先跑 `docs/06` §2.2 的 Phase 1**：坐标空间硬分箱 + 箱内平均池化，
> **零自由超参**，几十行代码。分出差距后，下面这四阶段才逐项上线，
> 那时它们是消融表的行。
>
> 尤其 λ：它在度量空间（米）与网格空间（格）里量纲不同、最优值必然不同，
> 各自调优等于给 G4 开小灶，**会把核心对照问废**。

```
K 帧 × 256 patch × d   （+ 每 patch 的度量坐标 p ∈ R³，由深度反投影）
      │
      ├─ Stage 0  当前帧 = anchor：全分辨率保留，一个 token 都不动
      │
      └─ 历史帧 (K−1 帧)：
           Stage 1  新颖度打分 s = 1 − max_{j∈N₃D} cos(Eᵢ,Eⱼ)  → 取 top-m
                    （去掉当前帧的冗余副本；固定预算，不用阈值）
           Stage 2  ⭐ 跨帧联合 ToMe 合并（K−1 帧的存活 token 混在一起，
                    不是每帧各压各的）→ 质心 (x̄,ȳ,z̄,t̄) + size
           Stage 3  按质心施加 4D RoPE
```

**为什么当前帧绝不池化**：即时动作由当前观测决定，把它模糊掉等于自断手脚。历史帧只需要提供"运动趋势"这种粗粒度信息，可以大幅压缩。

**为什么 Stage 2 必须跨帧联合**：这是"4D 池化"与"把 2D 池化做 K 遍"的分界线。
静止表面在 5 个历史帧里可见 → 塌成 1 个 token（size=5），这是跨帧联合合并的
自然结果，而不是额外机制。逐帧压缩拿不到这个。

**Stage 2 与 Stage 3 的顺序不能反**（5.4 坑 1）。

Token 预算示例（K=8）：`256(当前) + 7×48(历史) = 592`，相比朴素堆叠的 2048 降到 **29%**，相比单帧 256 只涨 2.3 倍。

### 4.2 Stage 1：新颖度打分

最朴素的版本是 patch 对齐的特征余弦距离，零参数、够快：

```
s_{k,i} = 1 − cos( E_{k,i} , E_{K,i} )        ← 只在图像网格上按 (h,w) 对齐
```

⚠️ **但这正是 G3（图像网格基线）的做法，不是我们的。** 它默认
「同一 (h,w) = 同一物体」，而机械臂不断从物体前面划过时这个默认是错的。
主方法在**3D 近邻**里找对应：

```
s_i = 1 − max_{j ∈ N₃D(i)} cos( E_i , E_j )       N₃D = 当前帧中度量距离最近的若干 patch
```

**取 top-m 而非卡阈值**——固定预算才能和 G2/G3 做公平对照。

> 用特征空间而非像素空间：对光照变化鲁棒，且语义上"物体动了"比"像素变了"更准。
> MuJoCo 无传感器噪声，静态背景像素差严格为 0，像素层会高估集中度（见 4.4）。

### 4.3 Stage 2：用什么池化算子——逐个评估

| 算子 | 优点 | 致命问题 | 结论 |
|---|---|---|---|
| **均值池化** (2×2 / 4×4) | 最简单、无参数、保留空间布局 | 把运动物体和背景一起抹平，**恰恰糊掉最该保精度的地方**，和我们的动机自相矛盾 | 只作 baseline |
| **最大池化** | — | ViT 特征不是激活图，跨 patch 取通道最大值语义上无意义 | 弱 baseline |
| **注意力池化 / Perceiver latent query** | 表达力最强、端到端可学、预算固定 | **输出 token 没有确定的空间位置** → 无法赋予 (x,y,z)，**直接和 4D RoPE 冲突** | 强 baseline，但与本方案架构不兼容 |
| **ToMe 式二部图软匹配合并** ⭐ | 天然内容自适应（自相似的背景会被合并，独特的前景被保留）；近乎免训练；**合并后的 token 有明确定义的位置 = 各成分的加权质心** | 相似度计算 O(n²)（常数很小，实测可忽略） | **选它作主算子** |

**选 ToMe 的决定性理由**：只有它在合并后仍能给出每个 token 的位置——`p̄ = Σ w_j p_j / Σ w_j`。没有这个性质，第 5 节的 4D RoPE 根本无从谈起。这不是性能取舍，是架构约束。

> ⚠️ **但这个约束不止 ToMe 满足。** 坐标空间硬分箱 + 箱内平均池化同样给出确定质心，
> 而且**零自由超参**——所以最小版本用它（`docs/06` §2.2 Phase 1），
> ToMe 排在 Phase 2 第一项。上表真正排除掉的是**注意力池化 / Perceiver**
> （输出 token 没有确定空间位置），那条排除是硬的。

#### ⚠️ 一个必须说破的张力：Phase 1 用的正是上表判为"只作 baseline"的均值池化

上表说均值池化"把运动物体和背景一起抹平，恰恰糊掉最该保精度的地方"。
**这个批评是对的，而 Phase 1 就是它。** 不能装作没这回事。

化解在于**量的是什么**：

- 上表评的是**绝对性能**——做最终方法，均值池化确实不够
- Phase 1 量的是**两个坐标系之间的差值**，G3 与 G4 **承受同样的handicap**，
  它在相减时抵消

**但抵消不是无代价的，真实风险有一条**：若算子粗到两组都被地板效应压住
（都掉到很低且都饱和），差值会被压向 0，**造成假阴性**。

所以 `docs/06` §3.2 的排查顺序里，**"分箱太粗盖住了差异 → 上 ToMe 再测一次"
是必查项**，不是可选项。Phase 1 打平 ≠ 创新点不成立；
**Phase 1 分出差距才是强结论**（粗算子都掩盖不住），
打平则必须升级算子再判一次。

**建议做法**：把池化算子做成可替换模块，四种全部消融。这正好对应 VLA-4D 自己的 Table 6（融合策略消融），审稿人吃这一套。

### 4.4 冗余度量的实测结果（2026-08）

假设"每帧只有一小部分区域在变化"已用 400 条轨迹（4 suite × 100）实测验证。
方法见 `scripts/measure_redundancy.py`：回放已记录的动作序列（评测确定性保证
画面逐帧一致），无需模型推理；16×16=256 个 patch。

#### 结果：假设成立

**Δt=1，前 10% 的 patch 贡献的变化占比**（均匀分布基准为 0.10）：

| Suite | 像素层 | **特征层 (DINOv2)** |
|---|---|---|
| Spatial | 0.831 | **0.700** |
| Object | 0.917 | **0.757** |
| Goal | 0.875 | **0.706** |
| Long | 0.818 | **0.707** |
| Gini | 0.89–0.92 | **0.80–0.85** |

特征层比像素层低 13–16 个百分点。原因：MuJoCo 渲染无传感器噪声，
静态背景的像素差严格为 0，**像素层是集中度的上界**。
特征层才是模型真正"看到"的冗余，也是应当采信的数字。

即便如此，**前 10% 的 patch 仍贡献 70–76% 的语义变化，是均匀基准的 7 倍以上。**

#### ⚠️ 修正一：压缩预算应随时间间隔递增，而非递减

本文档早先版本推测"历史帧预算随时间衰减（越久远压得越狠）——直觉上应该"。
**该直觉被数据推翻。**

前 10% 占比从 Δt=1 到 Δt=8 的降幅：

| | 降幅 |
|---|---|
| 像素层 | −3.5 ~ −5.2 个点 |
| **特征层** | **−11.2 ~ −15.8 个点** |

Spatial 从 0.700 降至 0.542；`frac_above_0.1` 由 0.119 升至 0.260（翻倍）。

**语义变化随时间间隔扩散得远比像素快。** 越久远的历史帧，与当前帧的差异
越分散在更多 patch 上，同等压缩率下的信息损失越大。

> **但须区分"信息损失"与"重要性"**：远期帧携带更多与当前帧不同的信息，
> 不等于这些信息对当前动作更重要。二者需由消融实验分别验证。
> 本节结论仅限前者。

#### ⚠️ 修正二：跨 suite 的集中度差异在特征空间基本消失

像素层排序 Object(0.917) > Goal(0.875) > Spatial(0.831) > Long(0.818)，
曾据此推断"集中度是任务结构的函数"。

特征层：Object(0.757) > Long(0.707) ≈ Goal(0.706) ≈ Spatial(0.700)
——**后三者几乎相同**。仅 Object 仍突出，因其十个任务布局完全一致、只换物体。

故该推断**只对 Object 成立**，其余三个 suite 的差异是像素层的假象。
设定 token 预算时仍取最坏情况（`src/analysis/token_budget.py`），
但不必按 suite 分别设参。

### 4.5 待定的设计参数（实验决定）

> ⚠️ 最后一条已从"待定"升级为**主方法**：跨帧联合合并就是 4D 池化本身，
> 不再是可选项。具体算法见 `docs/06` §2.2 Stage 2。

- 保留比例 r（高分 patch 保留多少）：由 `token_budget.py` 按"覆盖 90% 变化"
  反解得出，取各 suite 最坏情况，不再拍脑袋
- **⚠️ λ：合并相似度里几何距离的权重** `sim = cos(Eᵢ,Eⱼ) − λ‖pᵢ−pⱼ‖₂`。
  λ=0 退化成纯特征合并（远处的相似背景会被合到一起），λ 过大退化成纯几何聚类，
  只有中间一段才有想要的行为——**极敏感**。
  **且它是 G3/G4 的混淆项**（两个坐标系量纲不同），所以 **Phase 1 不带 λ**，
  Phase 2 加它时必须在 G3/G4 上做同样的扫描并报告曲线。见 `docs/06` §2.2
- **⭐ 4D RoPE 的通道预算与归一化尺度**：拨多少通道给 (t,x,y,z)、从高频端还是低频端拨、
  工作空间映到 [0,16) 还是别的范围。归一化尺度失配会直接造成频率混叠（5.4 坑 2），
  是 G4 若打平时**第一个要排查的地方**
- **历史帧预算随 Δt 递增**（已由 4.4 修正一确定方向，具体斜率待扫）。
  仍需验证的是"信息损失"是否等同于"对动作的重要性"——若远期帧的额外信息
  对当前动作无用，则递增预算是浪费
- **帧间隔 stride**：`scripts/analyze_stride.py` 定，不能取连续帧
  （K=8 连续帧只有 0.4 秒，跑出"历史没用"是必然的假阴性）
- K 取多少：`{2, 4, 8, 16}`；主线固定 K=8
- 合并后 token 的时间标记：size 加权均值 `t̄`（主方法）vs 时间区间 `[t_min,t_max]`（消融）

### 4.6 冻结模型的 token 预算消融（协议，2026-08 定稿）

4.4 证明了"变化确实集中"，但集中不等于**可丢**——模型可能依赖那些不变的
背景 token 来定位。所以在投入任何训练之前，先用冻结的官方 checkpoint
回答一个前置问题：**压到什么程度，成功率才开始掉。**

**代码**：`src/pooling/token_select.py`（算子）+ `scripts/run_token_ablation.sh`
（扫描）+ `src/analysis/collect_ablation.py`（汇总）。
介入点是 `modeling_prismatic.py:366` 的 `vision_backbone` 输出，
下游 attention mask 按 `shape[1]` 动态构建，改一处即可，不动模型代码。

**五个算子**（`--token_method`）：

| 算子 | 作用 |
|---|---|
| `random` | 最弱基线，随机保留 |
| `uniform` | 16×16 网格均匀采样，"不看内容的规则下采样" |
| `norm` | 按特征 L2 范数 top-k，常用的无监督显著性代理 |
| `avgpool` | 网格平均池化，ETA-VLA 那类"整块平均"的空间版对照 |
| `tome` | **主算子**，ToMe 二部图软匹配合并 |

**两个必须做对的实现细节**（都是能悄悄毁掉实验的坑）：

1. **合并要按 size 加权**。压到 12 个 token 需要迭代 5 轮，每轮取无权平均的话，
   一个由 32 个原始 patch 合成的 token 会和一个单独 patch 等权平均，
   合出来的东西不再代表任何区域。维护成分数 `size`，特征与位置都按它加权，
   等价于始终对原始 patch 取平均。
2. **输出要按质心位置重排**。ToMe 原版长在 ViT 内部，token 顺序无所谓；
   这里合并后的 token 要送进 Llama，**Llama 按序列下标施加 RoPE**。
   若按"保留的 A + 合并的 B"直接拼接，空间顺序就乱了，等于给冻结模型喂
   训练时没见过的排列——测出来的掉点会是排列扰动，而不是信息损失。
   `keep_random` 同理需要对索引排序。

**成本控制**：评测完全确定（docs/05 §3.2），第 k 次试验的初始状态由 init_files
固定，因此"每 task 前 5 次"是满量 500 局的**严格子集**——
基线不需要重跑，直接从已有轨迹里筛 `episode_idx < 5`。
这把每个配置压到 50 局（约 17 min），8 个预算点约 2.2h。
代价是 n=50 只能定位拐点的大致区间，拐点两侧再加量确认。

**两个结果都有意义**：压到 25% 不掉点 → 冗余确实可利用，方案成立；
压到 50% 就崩 → 模型对完整 token 有依赖，说明"先压后学"行不通，
得改成"边压边学"（压缩层参与微调）。后者不是失败，是把方案从
免训练路线钉死到训练路线上。

**⚠️ 适用范围**：OpenVLA 只吃单帧，没有历史序列，因此这里用不上 4.2 设计的
时间变化门控。测的是"单帧本身能压多狠"，是**下界**——历史帧相对当前帧的
冗余只会更高。

## 5. 4D RoPE 怎么做

### 5.1 基本形式：轴向分解，但**扩展**而非替换 1D RoPE

**这不是凭空发明**：Qwen2-VL 的 **M-RoPE** 已经在做 3 轴 (t, h, w) 分解，我们是把它推广到 4 轴。有现成实现可参考，风险低。

⚠️ **但不照搬 M-RoPE 的"把 head_dim 全拆成 4 组"**。那样**文本 token 的位置语义
也被改了**，对一个只做 LoRA 微调的 Llama-2 风险过高。采用的方案（`docs/06` §2.3）：

| 通道 | 谁用 | 位置 |
|---|---|---|
| ~70% | 全部 token | **原样 1D RoPE，完全不动** |
| ~30% | 仅视觉 token | 4 轴 (t,x,y,z) |
| | 文本 token 在这些通道上 | **单位旋转（恒等）** |

三个好处：① 预训练通路原封不动；② 消融把 4D 通道置恒等即退化成基线；
③ 绕开"文本坐标与视觉度量坐标怎么共存"这个 M-RoPE 式方案必须回答的问题。

### 5.2 相对 M-RoPE 的真正区别

**M-RoPE 用的 (h, w) 是图像网格坐标；我们用的 (x, y, z) 是深度反投影出的度量坐标。**

区别为什么重要：
- 图像网格坐标不携带真实几何，"第 3 行第 5 列"在不同视角下含义完全不同
- 度量坐标**视角无关**：同一物理位置无论被哪个相机看到，编码都一样
- 于是多路相机的 token 天然落在**同一个位置编码空间**里（扩展项，`docs/06` §6）

⚠️ **但这一条本身不是创新点**——SpatialVLA / HiST-VLA / STRING 都在做
"把度量 3D 坐标喂给位置编码"（§2.2）。创新点是它与**池化**的耦合：
合并后 token 的位置是各成分的**度量质心**，而质心距离恰是决定动作的量（§3 ②）。
**这个对照就是 G4 vs G3。**

### 5.3 相对 VLA-4D 的 Fourier STE 的区别（写作时的关键论据）

VLA-4D 用 Fourier 特征做时空嵌入（其式 3），是**绝对的、加性的**编码。
RoPE 是**旋转的、通过内积产生相对性**的：`q·k` 只依赖于位置之差。

**为什么机器人操作更需要相对位置**：真正决定动作的是"夹爪相对目标物体的偏移"，不是"夹爪在世界系的绝对坐标"。绝对坐标一换场景就失效，相对几何是可泛化的。

> 这是一条能站住脚的、说明"为什么用 RoPE 而不是 Fourier"的理由，比"RoPE 更先进"有说服力得多。

### 5.4 三个实现上必须注意的坑

**坑 1：RoPE 必须在池化之后施加，绝不能在之前。**
RoPE 本质是旋转。把旋转角度不同的向量做平均，模长会收缩、相位被破坏。
正确顺序：**先池化特征 → 算成分的加权质心位置 → 用质心位置施加 4D RoPE**。

**坑 2：度量坐标需要归一化，否则频率混叠。**
RoPE 原本为整数位置设计。米制坐标（LIBERO 桌面工作空间约 1m）直接塞进去，频率分配会失配。
**取法**：把工作空间包围盒按轴映射到 **[0, 16)**——与模型预训练时见过的 16×16
网格频率量级对齐；t 映到 [0, K)。这个尺度是超参，**G4 若打平，第一个排查它**。

**坑 3：四个轴的通道预算不必均分，且要决定从哪一端拨通道。**
t 的取值范围（K 个离散时刻）远小于 x,y,z 的连续范围，不需要均分——
在 5.1 的 ~30% 预算内，建议 x,y,z 各占大头、t 占一小份。
**从高频端拨**：高频通道在 2048 长的序列上早已绕圈，携带的可用长程信号最少。
这条要做消融，不能只凭直觉。

**坑 4：文本起始位置必须与存活 token 数无关。**
固定为 `K×256+1`。若它随池化率浮动，测出来的就又是位置扰动——
阶段 1 已经量化过这件事值 **−54 个点**（`docs/05` §7.4），是压缩本身的五倍。

## 6. 落到 OpenVLA 上的现实问题

必须提前知道这条路的工程量：

| 需要改的东西 | 现状 | 工作量 |
|---|---|---|
| 多帧输入 | OpenVLA 只吃单帧，论文局限性第 1 条就是这个 | 中——要改 processor 和 collator |
| 深度 | OpenVLA 完全不用深度；训练用的 RLDS 里也**没有**深度 | 小——`camera_depths=True` 回放动作序列离线缓存 patch 级深度（256 值/帧，约 38 MB/suite）。`measure_redundancy.py` 已经在回放，代码现成。**先验证回放 RGB 与 RLDS RGB 一致** |
| 4D RoPE | Llama-2 用的是 1D RoPE | 中——按 5.1 的**扩展式**方案只需在保留通道上叠加旋转，不动 1D 通路（替换式才是"大"） |
| 池化模块 | `src/pooling/token_select.py` 已有单帧 ToMe（size 加权 + 质心 + 重排） | 中——扩到跨帧联合合并 + 度量距离项 |
| 重新微调 | 改了输入输出就必须重训 | 4090 上约 12 h/次，主线共 4 次（`docs/06` §5） |

**曾经的岔路口，已经关闭**：

- **走 OpenVLA**：保住 970k 真实机器人轨迹预训练出的动作能力，但要自己动 1D→4D RoPE 的手术
- **走 Qwen2.5-VL**（VLA-4D 的选择）：M-RoPE 已是 3 轴，扩到 4 轴改动小；但没有机器人动作预训练

**已定：走 OpenVLA。** 两个理由，都是这半年跑出来的：
① 基线已复现（四 suite 74.1% vs 论文 76.5%）、自建微调配方已过硬门槛
（step 20 000 达 72.0% 对 76.0%，`docs/05` §8），换底座等于全部推倒；
② 5.1 的**扩展式** 4D RoPE 把"改动深"这条劣势基本消掉了——
不替换 1D 通路，只在保留通道上叠加，Qwen 的优势不再明显。

**冻结模型的池化消融也已完成**（4.6 协议，结果见 `docs/05` §7），
且产出了比预期更硬的东西：**位置编码值 −54 个点，是压缩本身的五倍**——
这就是 4D RoPE 的直接动机，也是全部后续工作的支点。

## 7. 实验顺序

> **2026-08 重排。** 完整设计与成本见 `docs/06` §3，这里只列骨架。

1. **OpenVLA 基线** —— 四 suite 跑满 + 自己的平滑度指标 ✅ *docs/05*
2. **冗余度量** —— patch 级变化分布，证明"只有一小部分区域在动" ✅ *4.4*
3. **冻结模型的 token 预算消融** —— 单帧能压多狠 ✅ *协议见 4.6，结果见 docs/05 §7*
   → 最硬的产出不是压缩曲线，而是**位置编码值 −54 个点，是压缩本身的五倍**
4. **G1 vs G0**：K=8 全量 vs K=1 —— 历史帧到底有没有用（前提检验）
5. **G3 vs G2**：patch 级 vs 帧级池化 —— 粒度
6. **⚠️ G4 vs G3**：度量 4D 坐标 vs 图像网格坐标 —— **核心创新，唯一必须赢的对照**
7. 消融与写作

**G4 vs G3 排在 11 月而非最后**：打平就是创新点不成立，必须留出转向时间。

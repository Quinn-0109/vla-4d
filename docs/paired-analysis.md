# 四组实验的结果归档与分析

配对分析不再扫描目录，也不按修改时间覆盖结果。先复制
`paired-manifest.example.json` 为 `paired-manifest.json`，核实后填写：

- 每个实验臂的准确 checkpoint 路径、训练种子和评测代码提交。
- 同一份固定训练子集清单的 SHA256，以及所有训练/评测协议字段。
- 每个逐局文件的路径与 SHA256。路径相对于清单文件；分段结果逐个列出。

Linux 上用 `sha256sum <文件>` 获取哈希。不要使用通配符自动挑选最新结果。
旧日志没有完整元数据：必须对照训练配置、评测日志后登记，无法确认时暂停分析。
哈希验证能防止文件变化，不能证明人工登记的实验来源真实；清单应与原始记录一起归档。
`dataset_sha256` 对应实际用于筛选轨迹的固定子集清单，不能填深度缓存路径或随意的标签。

执行：

```bash
python scripts/paired_analysis.py --manifest docs/paired-manifest.json
```

允许先明确登记 G3、G4 两臂，各臂必须具备 task 0、2–9 × episode 0–49 的
450 条主分析记录。task 1 可保留但不参与主分析。缺局、重复键（包括相同结果）、
坏 JSON、配置不同、哈希不符都会拒绝分析，不会取交集缩小样本或静默覆盖。
G3-full 必须独立归档，不能纳入此清单。核验通过只证明登记数据内部一致。

主效应与交互区间按逐局配对对比量计算，是描述性正态近似；它们不覆盖训练种子
方差，也不应当被解释为跨任务分布的泛化保证。固定初始态重复评测不增加独立样本。

下一步保持既定 G3-full 配置完成归因对照，补齐 M2/M3 逐局记录。
33%/38% 保留为后续资源投入阈值；正式结论报告差值及不确定性，不能仅凭阈值
证明等价、分解因果比例或认定方法有害。

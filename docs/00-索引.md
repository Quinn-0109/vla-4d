### ❌ 已证伪 / 已撤回（**写过、后来被自己的数据推翻**）

| 曾经写过 | 实际 | 出处 |
|---|---|---|
| 「2.7× 压缩免费」 | 跨 suite 复现后是 **−10.6 点**（p=1.6e-3） | `05` §7.5 |
| 「K=16 需要 40 GB 以上的卡」 | 19.2 GB。旧表测的是 LoRA 加在视觉主干上 | `05` §9.1 |

| K=8 微批吞吐表 / 「4×4 最优」/「30k 步 19.7 h」/「瓶颈在视觉主干」 | **全部实测于 K=1**（数据侧 K 静默退化）。真 K=8 是 2.79 s/步、23.3 h | `05` §10.1 |
| 「`peak_gb` 能发现 K 退化」 | **说反了**。池化后 K=8 与 K=1 显存持平（16.6 vs 16.3），能区分的是 s/步（4.4 vs 2.35） | `05` §10.1 |
| 「视觉特征缓存省 8 倍」 | 那是**视觉那一段**的倍数；视觉只占总耗时约 1/4，总体省 20% | `05` §11.2 |
| 「动作 token 准确率能判模型强弱」 | **不仅弱，而且会反向**：G0 的 acc 在 30k/50k 两点都高于 G2，成功率却分别低 18.8 / 16.2 点；官方 ckpt 训练集 acc 0.9958 却只有 48.2% | `05` §13.2 |
| 「30 000 步够用」 | **在 spatial 上定的，没重验就搬到 libero_10**。G0 的 acc 曲线最后 5000 步仍以 +0.0117/千步上升，几乎没减速 | `05` §13.2 |
| 「G0 的 24.8 点缺口是长程复利」 | 缺口在**拟合程度**上：同数据同路径，官方 acc 0.9958 而 G0 只有 0.705。复利解释未被推翻但已非主因 | `05` §13.2 |
| 「归一化 jerk 可跨任务安全比较」 | 需加限定：**它随子动作个数增长**，而 Long 按定义就是多子任务组合 | `05` §4.6、`06` §1.2 |
| 旧 novelty 论证「2D 剪枝隐含静态相机假设」 | 本设置只用第三人称静态相机，**该论证不成立** | `06` §1.3 |
| novelty 的「三条独立理由」 | 读原文后**两条不是我们的**：度量坐标做 PE 是 **SpatialVLA**（Ego3D PE，+27.3 点），按深度分配压缩配额是 **DepthCache**。剩下的唯一主张是**合取**——两侧用同一套坐标，而一致性本身有用 | `06` §1.3、§8.3 |
| G2 的 `acc=0.527` / `eval_only 0.638` / `0-20` | 全部作废 —— 那一轮训的是**单帧** | `05` §10.1 |
| 「评测 OOM 是 env 的 EGL 渲染上下文逐 task 泄漏」 | **碎片，不是泄漏**。报错里 PyTorch 占 20.66/22.68 GiB，non-PyTorch 约 1 GB 没在涨；显存列六个 task 全程 15.2–15.4 GB | `05` §13.2 |
| 「M3 的序列长应为 302，打出 300 就是 PE 退回 3 轴」 | **判据错**。序列长 = 1+N+文本长，随批里的语言指令抖动，**与臂无关**；同一份代码打出过 294/300/302，全是对的。真判据是 PE 轴数，已加进 `assert_arm_wiring` | `05` §13.3 ③ |
| 「容器里 `uptime` 能判容器是否重启过」 | 它读 `/proc/uptime`，那是**宿主机**的（本机报 96 天）。要看容器自己的启动时刻只能看 PID 1 | `05` §13.3 ⑤ |
| 「`/proc/meminfo` 能反映我们的内存余量」 | 容器里那是**宿主机**的数（1007 GB 总量 / 958 GB 可用），真限额是 cgroup 的 120 GB。差两个数量级且不报错 | `05` §13.3 ④ |
| 「子集覆盖率 66% 是三道闸各卡 p88 的算术」 | **失败按 task 聚集**，不是判据整体偏紧。只看分位数就下结论，没等交叉表 | `05` §12.3 |

> **「池化用的坐标系 ＝ 位置编码用的坐标系」**——这比"4D RoPE"本身重要，
> 因为 patch 级时空池化、度量 3D 表征、3D 坐标 RoPE 都各自有人做过，
> 没人把它们耦合在同一个度量 4D 坐标系里。
> 两个必须赢的对照：**G4 vs G3**（度量 4D vs 图像网格，**弱命题**）与
> **G4 vs M2**（一致 vs 错配，**强命题**，标题句的唯一直接证据）。
> 全部固定 token 预算 N=256，于是前提检验 **G2 vs G0** 也在同一预算上。
> **先跑零自由超参的最小版本**（§2.2 Phase 1），ToMe / λ 等一律压到 Phase 2。

| 脚本 | 作用 |
|---|---|
| `scripts/analyze_stride.py` | **定历史帧的采样间隔**。判据是「历史帧在多远之后就等同于同 episode 随便一帧」 |
| `scripts/check_replay.py` | ⭐ **G4/M2 的唯一前置**。验「同一初始状态 + 同一动作序列 → 仿真器能复现 RLDS 的画面」。对不上则缓存的深度属于另一个场景，而 G4 照跑不报错 |

| `scripts/check_wire.py` | ⭐ **在真 7B 上验挂点**。四项检查，后两项能证伪：改深度 → G4 变而 G3 不变（度量坐标真的进模型了）、G4 与 M2 的 logits 不同（PE 侧坐标真的起作用 = 强命题的通路存在） |
| `scripts/probe_vram.py` | 显存实测。`--sweep` 决策表，`--sweep_batch --K 8` 选 batch，**`--freeze_vision` 对齐实际训练配置**（不加就是错配置，见 `docs/05` §9.1），`--cameras 2` 双相机 |
| `src/common/lora.py` | LoRA 目标层选取。训练与显存实测**共用这一份**，防止两者配置不一致 |
| `scripts/prepare_finetune.sh` | `check` 体检 / `deps` 校正版本 / `data` 下数据集 |
| `scripts/finetune_single.py` | 单卡 LoRA 微调。`--bench_only True` 先测吞吐 |
| `scripts/finetune_kframe.py` | **K 帧微调**。六组共用这一个脚本，差别只在 `--arm`。有效批固定 16；G4/M2 因训练集深度缓存未就绪会直接拒绝 |
| `scripts/merge_lora.py` | adapter 合并成可评测的完整 checkpoint |

## 几条踩过的坑（省得再踩一遍）

1. **新开终端/tmux 会掉回 base 环境**。踩过四次。把 `conda activate` 写进
   `~/.bashrc`；各启动脚本已加前置检查。
2. **相对路径要在仓库根目录跑**。`git` 会向上找 `.git`，相对路径不会——
   在子目录里 `git pull` 成功但 `bash scripts/xxx.sh` 找不到文件。
3. **依赖腐烂**。2023–2024 年的包大多没锁传递依赖上界，pip 会拉来 2026 年的
   版本导致运行时崩溃。全部锁在 `setup/constraints.txt`，每条都写了原因。
4. **`p > 0.05` 不等于「两者相同」**。本项目曾以 n=50 报出「压缩免费」，
   加量到 n=200 后被推翻。等价性声明必须先算功效。见 `docs/05` §7.5。
5. **⚠️ 子集不是满量的无偏估计**，哪怕它是满量的**严格**子集。
   评测确定性只保证子集**可复现**，不保证它**有代表性**。
   本项目用 `episode_idx < 5` 的 50 局判「硬门槛通过」（72.0% vs 76.0%, p=0.65），
   满量 500 局推翻：74.0% vs 84.2%，差 10.2 点、p=7.3e-05——
   那个子集恰好对官方 checkpoint 特别难，把真实差距掩盖了六个点。
   **n=50 已第三次误导本项目。判定一律用满量。** 见 `docs/05` §8.2。
6. **就地修改的函数**。`normalize_gripper_action` 原地改并返回同一对象，
   不先复制会让"模型输出"和"执行动作"两个字段记成同一个值。

## 阶段 B · 多帧输入（最大的一块工程，也是唯一的必经之路）

**问题**：OpenVLA 是**单帧**模型。方案的全部价值在历史帧上，
但冻结模型没见过多帧输入，**这一步开始必须训练**。

需要做的：

1. **数据**：`bash scripts/prepare_finetune.sh data` 下载
   HF 上的 `openvla/modified_libero_rlds`。
   **实测每个 suite 约 1.9 GB（16 个 tfrecord 分片），四个加起来 ~8 GB**，
   两分钟下完——原先"数十 GB"的估计错了一个数量级，磁盘不是约束。
   真正吃盘的是微调产物：`finetune.py` 最后存合并权重，一份 15 GB。按 `docs/01` 附录 E 的五项处理复核
   （尤其 no-op 过滤，漏了模型会学成不动）
   —— 该数据集名字里的 `_no_noops` 后缀就是这一步的产物
2. **依赖**：`bash scripts/prepare_finetune.sh deps`。
   ⚠️ `peft` 必须钉 `0.11.1`（openvla 的 pyproject 就是这么写的）。
   LoRA 实现的行为差异**不会报错**，只会让微调结果对不上官方水平，
   属于最难查的那类问题。装完要重跑一次评测冒烟测试，确认没弄坏推理链路。
3. **输入构造**：把 K 帧堆成 `K × n_token × d`，改 `PrismaticProcessor` 与 collator。
   `scripts/probe_vram.py` 里的 `patch_multiframe` 已经是这个的草图
4. **基线微调**：K=1 复跑一遍 LoRA，确认我们的训练流程能复现官方 checkpoint 的水平
   —— 这一步不能跳，否则后面所有对照都没有可信的地基

### 显存实测结果（2026-08，已完成）

`scripts/probe_vram.py --sweep`，RTX 4090 24 GB，flash-attn 2.5.5，
LoRA r=32 all-linear，batch=1。峰值显存（GB）：

| 配置 | K=1 | K=2 | K=4 | K=8 | K=16 |
|---|---|---|---|---|---|
| 推理，不压缩 | 15.4 | 15.6 | 15.9 | 16.7 | 18.2 |
| 推理，keep=96 | 15.2 | 15.3 | 15.5 | 15.8 | 16.3 |
| 训练，不压缩 | 18.2 | 20.3 | **OOM** | OOM | — |
| 训练，不压缩 + 梯度检查点 | — | — | 18.5 | **21.2** | OOM |
| 训练，keep=96 | 17.2 | 18.2 | 20.4 | **OOM** | — |
| 训练，keep=96 + 梯度检查点 | — | — | — | **20.1** | OOM |

权重本身占 15.13 GB，留给激活的全部预算只有约 8.6 GB。

**① 预测错了：不压缩的 K=8 基线跑得动。**
先前判断"要对照的那个基线是最跑不动的那个"，只在不开梯度检查点时成立，
而那不是实际会用的配置。**"压缩是使能而非优化"这个说法在 24 GB 卡上不成立**，
不采用该叙事。好消息是核心对照实验（阶段 C）能在 4090 上做，不必租大卡。

**② 真正的杠杆是梯度检查点，不是压缩。**
K=8 时压缩与不压缩只差 1.1 GB（20.1 vs 21.2）——检查点已经把 LLM 的激活
消掉了大半，压缩再省的空间有限。压缩换来的是**速度**（检查点本身要付
30–40% 吞吐，序列短也更快），不是显存。

**③ token 数不是全部——这条给出一个设计决定。**

- K=2 × keep=256 = **512** token → 20.3 GB
- K=4 × keep=96 = **384** token → 20.4 GB

token 更少反而更费。因为**压缩发生在视觉主干之后**：K 帧要各过一次
DINOv2+SigLIP，每次的激活都要留着反传，这部分与压不压缩无关。
两点粗算（仅供定量级参考）：每帧视觉主干约 **0.5 GB**，LLM 约 **6.25 MB/token**，
keep=96 时视觉那部分占每帧成本的四成多。

→ **视觉主干应当冻结，不挂 LoRA。** 官方 `finetune.py` 用
`target_modules="all-linear"`，LoRA 会挂到视觉主干上，多帧时这笔开销乘 K。
冻掉它既省显存，也更贴合本方案——我们改的是 token 表示与位置编码，
不是特征提取器。

## 阶段 C · 前置控制：历史帧到底有没有用

> 本阶段由一个提问补上：**若视觉主干冻结、只是把多帧特征合并送进 LLM，
> 视觉特征本身没有变好，历史帧凭什么弥补单帧的判别缺陷？**

### C.1 先把概念说清楚：历史帧不修复特征质量

**它确实不能。** 若 DINOv2+SigLIP 在第 t 帧分不清红杯子和橙杯子，
t−1…t−7 帧里同一个静止杯子的特征同样分不清；合并一堆同样糟糕的特征，
得到的还是同样糟糕的特征。凡是宣称"多帧提升视觉判别力"的说法，
除非动了编码器，否则站不住。**本项目不作此主张。**

历史帧提供的是**任何单帧都不包含的信息**，与特征质量是正交的两个轴：

| 来源 | 为什么单帧拿不到 |
|---|---|
| **只能由变化观测的状态** | 同一个半开的夹爪，"正在闭合"与"正在张开"的图像可以完全一样。速度、方向、"刚抓住还是刚脱手"都属此类 |
| **遮挡与记忆** | t−5 帧可见、t 帧被机械臂挡住的物体。当前帧不含它，编码器再好也编不出来 |
| **多步任务的阶段消歧** | "把碗放进抽屉再关上"——"正要开抽屉"与"刚放完碗"的画面可以几乎一致，区分它们需要知道自己刚做过什么 |

一句话：**历史帧补的是信息的可得性，不是特征的判别力。**

### C.2 ⚠️ 这个提问暴露的真实缺口

**我们从未验证过历史帧在 LIBERO 上是否有用。**

OpenVLA 是单帧模型，Spatial 拿到 84%。若 K=8 加上池化仍是 84%，
等于什么都没做。而原先的阶段 C（2D 池化 vs 4D 池化）**默认了多帧优于单帧**——
前提若不成立，就是在比较两种压缩废物的方法。

因此这组控制实验必须补，且**排在 2D vs 4D 之前**。

### C.3 实验设计

| 组 | 配置 | 目的 |
|---|---|---|
| C-1 | K=1（自建配方，已完成，Spatial 72.0%） | 单帧参照 |
| C-2 | K=8 不压缩，**LIBERO-Long** | 历史帧到底有没有用 |
| C-3 | K=1，**LIBERO-Long** | Long 上的单帧参照 |
| C-4 | K=8 不压缩，Spatial | 验证「单步任务里历史帧价值低」的预测 |
| **C-5** | **K=8，但历史帧取自随机时刻**（打乱时序或取自同任务其他 episode），Long | **排除「收益并非来自时序信息」的混淆** |

**C-5 是关键对照，不能省。** 它与 C-2 的计算量、序列长度、参数量完全相同，
**唯一区别是时间信息是否真实**。若真历史不显著优于假历史，那 K=8 的收益
来自更多有效训练或正则效应，而非时序推理——那样整个方案的前提就是假的。

没有这一组，「K=8 > K=1」这个结果会有一个无法排除的解释：
我们的 K=1 基线偏弱（Spatial 上 72.0% 对官方同批次 76.0%），
头部空间更大，任何增加输入的改动都可能带来提升。

**为什么主战场是 Long 而非 Spatial**（预先登记的预测）：

C.1 的三条机制里，Spatial / Object / Goal 大多是**单步、基本全可观测**的任务，
历史帧的边际价值本就低。预期效应最大的是 Long——多步、有阶段歧义。
而 OpenVLA 恰恰在 Long 上最弱（52%）。

本项目自己的数据独立支持这一判断：**Long 的归一化 jerk 是 Spatial 的 18.7 倍**
（`docs/05` §4.4）。轨迹极度不平滑，正是"不知道自己处在哪一步、反复试探"的症状。

**预测**（预先登记）：
1. Long 上 C-2 显著优于 C-3
2. Spatial 上 C-4 与 C-1 差异不显著
3. **C-2 显著优于 C-5**（真历史 > 假历史）
4. **收益集中在有遮挡或阶段歧义的时刻**，而非均匀分布——
   见下方「分层分析」
若两个 suite 上历史帧的收益一样大，说明它带来的不是时序信息而是别的东西
（比如等效于数据增强），那对本方案的叙事是坏消息，需要重新解释。

**分层分析（不只看总成功率）**：有工作指出 VLA 中「存储的历史信息很大程度上是
当前帧的冗余副本」，且因果干预显示**历史只在当前帧被严重遮挡时才被调用**。
若属实，预测就该更强也更可证伪：**收益应集中在遮挡/歧义时刻**，而非均匀分布。
我们有 per-task 分解与逐步轨迹，足以做这个分层。
均匀分布的收益反而是警号——那更像正则效应。

这条同时约束了 4D 池化的设计：**压缩后的 token 必须携带"当前帧没有的新信息"**，
否则只是在压缩冗余副本（`docs/04` §4.2 的时间变化门控正是为此）。

### C.4 三种结果的走向

| 结果 | 含义 | 下一步 |
|---|---|---|
| Long 上 K=8 显著更好 | 前提成立 | 进入阶段 D（2D vs 4D 池化） |
| 两个 suite 都打平 | LIBERO 测不出时序推理，**或**模型没学会用历史 | 后者指回位置编码——先给多帧加 4D RoPE 再测一次；仍打平则换基准或换方向 |
| Long 上 K=8 反而更差 | 更长的序列在没有正确位置编码时是负担 | 与阶段 1 的发现一致，直接进 4D RoPE |

注意后两种都不是死路：它们把矛头指向位置编码，而那正是本项目已量化过的地方
（位置修正值 +54 点，压缩本身只值 −10.6 点，见 `docs/05` §7）。

### C.5 与阶段 1 发现的连接

历史帧的信息要被用上，模型必须能分辨每个 token **来自哪一帧、在哪个位置**。
阶段 1 已经量化了这件事的重要性：位置编码错了值 −54 个百分点。

所以「多帧 token 需要 (t,x,y,z) 坐标」不是设计偏好，是实测支持的推论。

**冻结视觉主干在这个叙事里反而是干净的**：我们不声称改进了视觉表征，
我们改的是**模型索引时空信息的方式**——而这恰好可以在冻结编码器的前提下做。
这也让贡献的边界清晰：任何收益都不能归因于"更好的特征"。

### C.6 ⚠️ 范围声明：不主张在 LIBERO 上刷 SOTA

**OpenVLA-OFT 在 LIBERO 上已达 95.0%**（`docs/04` §2.5，出处 Drop-Then-Recovery）。
关键在于：**OFT 的收益来自动作分块与并行解码，输入侧没有历史帧。**

这有两层含义，都必须写进论文而不是回避：

1. **Long 的困难未必主要来自「看不到历史」**，可能主要来自动作表示。
   评审会直接问「为什么不用 action chunking」。
2. 因此本项目的主张**不是**「我们把 LIBERO-Long 做得更好」，而是
   **固定 token 预算下，4D 池化比 2D 池化保留更多任务相关信息**——
   这是表示效率的主张，与 OFT 不在同一维度，可以正交叠加。

这与 `docs/04` §2「叙事必须重构」是同一条线：效率是副产品，
**表示才是论点**。天花板的存在不否定表示层面的贡献，但会否定
「刷分」式的叙事——后者本项目不采用。

### C.7 已知的三条技术风险（来自外部评估，已核验）

**① 感知混淆 / Motion Inconsistency** —— 不加选择地堆叠历史帧，
在「观测相似但所需动作不同」时会混淆模型。这**支持**本方案的选择性池化
（变化门控 + 4D 位置），反对朴素拼接。C-2 用的正是朴素拼接，
因此它既是「历史有没有用」的检验，也是「朴素做法够不够」的参照。

**② Token 同质化** —— 激进合并会削弱驱动注意力的关键 token 分量，
使 token 在深层逐渐失去区分度。**这条直接对应本项目已测到的未解释残差**：
位置修正后 `keep=64` 为 34.0%，而保持长度的 `expand@64` 为 70.0%，
36 个点的差距是位置修正**没能**关掉的（`docs/05` §7.4）。
先前假设是注意力质量（ToMe 的 proportional attention），同质化是同一现象的
另一种表述，且给出了可监控量：**深层 block 中视觉 token 的注意力份额**。
→ 待办：在 4D 池化实现里加这项监控。

**③ ~~位置编码的「距离惩罚」~~ —— 方向相反，不成立**

外部评估称「压缩视觉 token 使文本与视觉 token 的相对距离变大，
RoPE 的位置衰减会惩罚远处的视觉 token」。**方向反了**：
压缩 256→64 后语言块从 257 号挪到 65 号，距离**变小**而非变大。
而 `fixpos` 做的正是把距离**还原**成未压缩时的样子
（视觉 token 拿回 1..256 中的质心位置，语言块仍从 257 起）。

真正未被 fixpos 关掉的残差是上面那 36 个点，其解释是 ② 而非距离。
记在这里是因为：**这类"方向听起来合理但符号相反"的论断最容易被采信**，
而按它去改设计会南辕北辙。

### C.8 评测协议与成本

**⚠️ 评测必须用 n=500（满量 50 trials/task），不能用 n=50。**

功效分析见 `docs/05` §8.3：n=50 只能检出 25 个百分点以上的差异，
而阶段 C 期待的效应量是 10–15 个百分点。用 n=50 做这组实验，
等于预先注定得到「不显著」，再把它误读成「历史帧没用」。

| 要检出的效应 | 每组所需 n |
|---|---|
| 15 个百分点 | ~162 |
| **10 个百分点** | **~356** |

**训练步数固定 20 000**，不做优化：现有数据不足以支持「15 000 就够」
（10k/15k/20k 在 n=50 下互不可区分），在不可靠的数据上省钱是最差的省法。

| 项 | 单组 | 五组 |
|---|---|---|
| 训练（20 000 步） | 11.6 h ≈ ¥24 | 58 h ≈ ¥120 |
| 评测（n=500） | 2.75 h ≈ ¥6 | 14 h ≈ ¥30 |
| **合计** | | **~72 h ≈ ¥150** |

K=8 的显存已实测可行（20.1–21.2 GB，见阶段 B），但吞吐会低于单帧，
实际耗时需在 C-2 开跑前用 `--bench_only True` 复测。

## 阶段 D · 2D 池化 vs 4D 池化（核心创新验证）

> 仅在阶段 C 确认历史帧有用之后才做。

`docs/04` §7 列的核心对照：**固定 token 预算**，比较

- 2D 池化：每帧独立压缩（对应现有的一堆 token pruning 工作）
- 4D 池化：跨帧联合压缩，合并 token 带 (t, x, y, z) 坐标

这是唯一能证明"在 4D 上做"不是包装的实验。
**若两者打平，方案的创新点就不成立**，要及早知道，所以排在 4D RoPE 之前。

预期能用上的杠杆（`docs/04` 4.5）：同一物理位置在多帧都静止 →
合成一个带时间区间的 token。这个如果成立会是最漂亮的点。

## 阶段 E · 4D RoPE + 完整方案

设计已写好（`docs/04` §5），轴向分解从 M-RoPE 的 (t,h,w) 推广到 (t,x,y,z)，
用**度量坐标**而非图像网格坐标。三个坑已记录在 5.4。

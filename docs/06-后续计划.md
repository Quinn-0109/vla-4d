## 0. 要保护的那一句话

```
        ┌────────────────────────────────────────┐
        │   池化用的坐标系 ＝ 位置编码用的坐标系   │
        │      Pooling Coord = PE Coord          │
        └────────────────────────────────────────┘

                   Metric 4D Space
                          │
              ┌───────────┴───────────┐
              ↓                       ↓
         Patch Pooling            4D RoPE
              │                       │
              └───────────┬───────────┘
                          ↓
                  同一套 (t, x, y, z)
```

**这比"4D RoPE"本身重要。** 理由见 1.1：patch 级时空池化有人做过（STTM），
度量 3D 位置表征有人做过（SpatialVLA / HiST-VLA），3D 坐标上做 RoPE 也有人做过
（STRING）。**没人做的是把这两件事放进同一个度量 4D 坐标系里耦合起来。**
写作时这是标题句，不是某一节的小结。

落到流程上：

```
K 帧 → K×256×d → 反投影出 4D 坐标 → 按该坐标池化到 N 个 token
                                    → 按同一坐标施加 4D RoPE → LLM
```

**核心主张**：固定 token 预算下，池化与位置编码共用**度量 4D** 坐标，
优于共用**图像网格 + 时间**坐标。

⚠️ **这个框是强命题，要有专门的实验撑。**
"度量 4D 比图像网格好"只是**弱命题**；"两者一致本身带来增益"才是框里写的那句。
G4 vs G3 只检验前者——必须加**错配臂 M2**（度量池化 + 网格 PE）才能检验后者。
设计见 3.0.2。**没有 M2，标题句就只能降级写。**

⚠️ **实现上先做最小版本，不要一上来把算子锁死**（§2.2）。
"ToMe + 新颖度打分 + λ 几何项 + size 加权质心"是不是最终形态，现在还不知道。

## 1. 定位：我们卡在三条线中间

| | 做法 | 缺口 |
|---|---|---|
| **VLA-4D** (2511.17199) | 历史序列 + 3D 位置嵌 1D 时间 → 4D embedding，动作侧扩 delta-time | **不做任何采样/池化**，token 数随 K 线性膨胀 |
| **4D-VLA** (2506.22242) | memory bank + **frame-wise** 下采样，相对位置编码 | **粒度太粗**：丢帧就丢时间分辨率，且帧内空间冗余完全没动 |
| **STTM** (2507.07990, ICCV'25) | 帧内四叉树合并 + 沿时间定向配对合并 | **patch 级时空池化已经有了**，但在 **2D 图像网格 + 时间**里；Video LLM，非 VLA |

**我们的位置**：保全部 K 帧（时间分辨率不损失），在帧内 + 跨帧做 patch 级池化
（空间冗余去掉），且池化与位置编码共用**度量 4D 坐标**。

### 1.1 ⚠️ novelty 必须精确表述，否则一句话被打掉

2026-08 文献核查的三条硬事实：

1. **patch 级时空池化不新** —— STTM 已做（2D+时间，免训练，Video LLM）
2. **VLA 里注入 3D 位置不新** —— SpatialVLA（深度估计器→patch 位置编码）、
   HiST-VLA（反投影到 3D，MLP 加性编码）、GST-VLA（2603.09079）
3. **⚠️ 3D 坐标上做 RoPE 不新** —— STRING 系列已用于机械臂，真机抓取 65%→74%，
   且强调平移不变性对操作任务的价值

所以**不能说**"我们把 RoPE 用到 3D/4D 坐标上"，也不能把"4D RoPE"当卖点——
那是 STRING 已经占掉的位置。能站住的只有交集，也就是 §0 那个框：

> **池化与位置编码共用同一套度量 4D 坐标系。**
> 合并后 token 的位置就是各成分的度量质心 (x̄, ȳ, z̄, t̄)，RoPE 直接吃这个质心，
> 中间没有任何坐标系转换。
> 现有工作里这两件事**各做各的**——池化的（STTM）不管合并后 token 的位置语义，
> 编码位置的（SpatialVLA / HiST-VLA / STRING）不池化。

这个耦合不是把两个模块拼在一起，是**互相需要**：
没有质心就没有 4D RoPE（`docs/04` §4.3 的算子选型是架构约束，不是性能取舍），
而池化若不在度量空间做，质心就没有几何意义（1.2 ①③）。

**这才是论文的论点。4D RoPE 只是它的实现手段之一。**

⚠️ **但论点越强，越需要专门的实验。**"两者一致"是强命题，
而 G4 vs G3 比的是**两组都一致、只是坐标系不同**——它撑不起这句话。
撑得起的是**错配臂**：度量池化配网格 PE（M2）。见 3.0.2 的 2×2。

### 1.2 为什么"4D"不是包装：三条可证伪的理由

> ⚠️ 本节替换 `docs/04` §3 的旧论证。旧论证是「2D 剪枝隐含静态相机假设，
> 腕部相机打破它」——但 OpenVLA 在 LIBERO 上只用第三人称静态相机，
> 静态相机下图像坐标跨帧本就可比，**旧论证在本设置下不成立**。
> 下面三条**在单个静态相机下依然成立**，因此腕部相机被移出主线。

**① 深度阻止错误合并（池化侧）**

图像网格里，两个 patch 在同一 (h,w)、不同帧，会被判为"同一位置"而合并。
但机械臂**不断从物体前面划过**：t−5 帧那个格子是背景，t 帧是夹爪。
合出来的 token 不代表任何真实表面。度量坐标下 z 相差十几厘米，直接分开。
→ **这是遮挡/去遮挡频繁发生的操作任务里最实际的收益。**

**② 度量坐标与操作相关的空间关系更对齐（编码侧）**

合并后 token 的位置是质心。RoPE 通过内积产生相对性，`q·k` 只依赖位置之差——
所以"质心距离"这个量会直接进到注意力里。图像网格下它是**像素距离**，随视角变化；
度量坐标下它是**厘米数**。

> ⚠️ **这条的表述必须克制，它是三条里最弱的一条。**
>
> 能说的：度量坐标提供了一种**几何感知的关系表征，与操作任务里真正起作用的
> 空间关系更对齐**（more directly aligned with manipulation-relevant
> spatial relationships）。
>
> **不能说**："RoPE 的距离就是动作距离，所以一定更适合动作预测。"
> 这条因果链太强。审稿人一句**"视觉 token 之间的 3D 欧氏距离，凭什么等同于
> 动作空间里的距离？"**就能问倒——而实验若不够漂亮，我们答不上来。
>
> 写作时把"更对齐"和"就是"这两种说法分清楚，别在正文里滑过去。

> 这条同时解释了 ETA-VLA 为何**刻意 RoPE-free**（`docs/04` §2.5）：
> 在 2D 网格上 RoPE 的距离偏置是噪声。**同一机制换个坐标系，从缺陷变成特性。**

**③ 预算分配有了物理判据**

"离夹爪/目标近的 patch 重要"在度量空间可以直接说；图像网格里说不了——
一个远处背景 patch 在像素上可以紧挨着夹爪。

**①③ 属于池化，② 属于编码。三条都指向同一套坐标——这就是耦合的理由。**

⚠️ 注意 **G4 vs G3 直接检验的是 ①③，不是 ②**。②（对齐得更好）是解释性的，
本实验设计**证伪不了它**，所以它只能作为动机写，不能作为结论写。

## 2. 方法：要实现的四件事

### 2.1 K 帧输入构造

- 堆成 `K × 256 × d`，改 `PrismaticProcessor` 与 collator。
  `scripts/probe_vram.py` 的 `patch_multiframe` 是草图
- **边界处理**：t < K 时**重复最早可得的那一帧**。训练与评测**共用同一个函数**，
  否则 episode 开头（恰是决定成败的抓取阶段）行为会系统性偏移
- **帧间隔 stride**：见 4.1，不能取连续帧

### 2.2 patch 级 4D 池化：**先做最小版本，不要一上来把算子锁死**

> 这一节曾把实现写死成"跨帧 ToMe + 新颖度打分 + λ 几何项 + size 加权质心 +
> Stage 0/1/2/3"。**研究计划可以这么写，代码不能这么开工。**
> 要验证的命题只有一个：**metric 4D pooling 是否优于 image-grid pooling。**
> 上面那一整套是不是最终形态，现在没有任何证据。全部同时上线，
> 一旦 G4 ≈ G3，你分不清是**坐标系没用**还是**某个环节没调好**。

#### ⚠️ 更要命的是：λ 本身就是 G3/G4 的混淆项

```
G4:  sim = cos(Eᵢ,Eⱼ) − λ‖pᵢ−pⱼ‖₂          p 的单位是米
G3:  sim = cos(Eᵢ,Eⱼ) − λ‖(h,w)ᵢ−(h,w)ⱼ‖₂   单位是格子数
```

**两个 λ 量纲不同，最优值必然不同。** 于是任何取法都会被反问：

- 两边取同一个数值 → 荒谬，量纲都不一样
- 各自调优 → **"G4 赢是不是因为你把它的 λ 调得更好？"**

**核心对照被一个超参毁掉。** 而 λ 本身还极敏感：
太小退化成纯特征相似度（远处的相似背景会被合到一起），
太大退化成纯几何聚类（特征完全不起作用），只有中间一段才有想要的行为。

#### Phase 1 · 最小版本：**零自由超参**的坐标空间分箱

固定输出预算 N。把坐标空间划成 N 个箱，箱内平均池化。就这样。

| | G3（图像网格） | G4（度量 4D） |
|---|---|---|
| 坐标 | (t, h, w) | (t, x, y, z) |
| 分箱 | 时间 × 图像网格 → N 格 | 时间 × 度量包围盒 → N 个体素 |
| 池化 | 箱内特征平均 | 箱内特征平均 |
| token 位置 | 箱内 patch 坐标均值 | 箱内 patch 度量质心 |
| 位置编码 | 按 (t,h,w) 施加 | 按 (t,x,y,z) 施加 |

四个好处：

1. **没有在两臂之间取值不同的自由参数。** 空间轴的箱数由预算按确定性规则求出；
   时间轴的箱数 `n_t` 是显式的**无量纲整数、两臂取同一个值**，作为消融整组扫描。
   （⚠️ 曾以为可以完全不给参数，实测发现那会让跨帧合并几乎不发生，见 3.0.5 ③）
2. **质心是平均池化的副产品**，天然存在，4D RoPE 直接可用——
   §0 那个"池化坐标 = 位置编码坐标"的框，在最小版本里就已经成立了
3. 确定性、无初始化敏感、几十行代码
4. **两边跑同一份代码，只换传进去的坐标张量** —— 这是最强的对照形式，
   连"实现不一样"这种质疑都堵死了

**它比 ToMe 粗，但我们量的是差值不是绝对值**，G3/G4 承受同样的 handicap，相减时抵消。

⚠️ **但要认下这个方案唯一的真实代价**：Phase 1 用的正是 `docs/04` §4.3
那张表判为"只作 baseline"的均值池化（"把运动物体和背景一起抹平"）。
若算子粗到两组都被**地板效应**压住，差值会被压向 0，**造成假阴性**。

所以判读规则要非对称：

| Phase 1 结果 | 怎么判 |
|---|---|
| **G4 > G3** | **强结论**——坐标系的作用大到连粗算子都掩盖不住 |
| **G4 ≈ G3** | **不能判死刑**，必须升级到 Phase 2 的 ToMe 再测一次（§3.2 排查③） |

#### ⚠️ Phase 1 实现上会立刻撞到的一件事：占用是不对称的

G3 的图像网格箱**永远满占**（每个 (h,w) 都有 patch）；
G4 的度量体素**天然稀疏**——patch 全贴在物体表面，空间大半是空的。
所以"划成 N 个箱"在两边不是同一件事，而 token 预算必须严格相等。

**取法**：只数**非空箱**（3.0.5 ③ 的贪心规则），再按箱内 patch 数排序取前 N，
不足则补空 token 并在 attention mask 里屏蔽。

⚠️ **实测发现一个反向的问题**：G4 未必"占满"，反而可能**够不到** N。
合成深度下 G4 只用掉 161/256 槽而 G3 用掉 242——把两臂拉平（`enforce_n`）后
公共预算被 G4 拖到 161，等于三组都损失 37% 的预算。
合成深度退化是主因，但**机制是真的**：G3 的网格箱数与数据无关，
G4 的体素占用取决于场景。真值深度缓存好后**必须重测**；仍偏低则要调
`metric_extent` 的工作空间包围盒。

> **要预先说清楚，不要等审稿人问**：这等于让 G4 获得了**内容自适应的分辨率**
> （物体密集处箱多，空处不占预算），而 G3 没有。
> 这不是混淆项，是**度量坐标的固有性质**——离开度量空间就没有稀疏性可言，
> 所以它属于处理效应的一部分。但必须在论文里明写，
> 而不是让它作为一个"没说的优势"藏在实现里。

#### Phase 2 · 只在 Phase 1 分出差距之后才做

按顺序单独上线，**每次只加一样**，各自留消融位：

| 顺序 | 加什么 | 为什么排这个位置 |
|---|---|---|
| 1 | ToMe 二部图软匹配替掉硬分箱，size 加权质心 | 内容自适应，是最可能带来增益的一项 |
| 2 | 新颖度打分（去掉当前帧的冗余副本） | 独立于算子，可单独开关 |
| 3 | 当前帧 anchor 保护 | 同上 |
| 4 | 相似度里的几何项 λ | **最后加，且必须在 G3/G4 上做同样的扫描并报告曲线**，否则 1 的问题重演 |
| 5 | **M3 = 度量池化 + MLP 加性编码**（HiST-VLA 那套） | 答"为什么不用 HiST-VLA 的编码器"。⚠️ 它检验的是 **RoPE vs MLP 这个机制**，两边坐标系仍一致——**回答不了强命题**，别和 M2 混为一谈（3.0.2） |

这四条在 `docs/04` §4.1–4.3 有完整设计——**那是候选方案，不是定案。**

#### 代码上必须留的口子

池化算子做成可替换模块，签名固定：

```python
pool(E, coords, budget) -> (E_pooled, coords_pooled, assign)
#   E:      (T, d)      token 特征
#   coords: (T, D)      D=3 → (t,h,w)；D=4 → (t,x,y,z)
```

**G3 与 G4 的唯一差别就是传进去的 `coords`。**
`src/pooling/token_select.py` 已有的 `return_pos` / `return_assign` 接口
就是照这个设计的，直接扩即可。

**两件与算子无关、必须做对的事**（换算子也不能丢）：

- **输出按 (t̄, 质心空间序) 排序**。乱序等于给模型喂没见过的排列，
  测出来的掉点会是排列扰动而非信息损失（`docs/04` §4.6 记着这个坑）
- **⚠️ 顺序不能反**：RoPE 本质是旋转，把旋转角不同的向量做平均会收缩模长、
  破坏相位。必须 **先池化 → 算质心 → 再施加 RoPE**（`docs/04` §5.4 坑 1）

"静止表面在多帧可见 → 塌成一个带 size 的 token"这个漂亮结果，
在 Phase 1 的分箱下也会自然出现（同一体素跨帧的 patch 落进同一箱），
不必等 ToMe。

### 2.3 4D RoPE：**扩展**而非替换 1D RoPE

Llama-2 是 1D RoPE。直觉做法是照 M-RoPE 把 head_dim 拆成 4 组分别编码 (t,x,y,z)，
但那样**文本 token 的位置语义也被改了**，对一个只做 LoRA 微调的预训练模型风险过高。

**采用的方案**：保留原 1D RoPE 通路，**另拨一部分通道**给 (t,x,y,z)。

| 通道 | 谁用 | 位置 |
|---|---|---|
| ~70% | 全部 token | **原样 1D RoPE，完全不动** |
| ~30% | 仅视觉 token | 4 轴 (t,x,y,z)，t 占 1/4 不到（取值范围只有 K 个离散时刻） |
| | 文本 token 在这些通道上 | **单位旋转（恒等）** |

三个好处：① 预训练通路原封不动；② 消融只需把 4D 通道置恒等，天然退化成基线；
③ 绕开了"文本坐标与视觉度量坐标怎么共存"这个 M-RoPE 式方案必须回答的问题。

**已实现**：`src/pooling/rope4d.py`，6 项 CPU 自测全过。验到的性质：
4D 通道置恒等后逐位退化成教科书 1D RoPE；文本 token 在 4D 通道上确实是单位旋转；
**`q·k` 在坐标整体平移下不变**（§1.2② 全部压在这条上，数值验过 +1/−3.5/+100）；
文本位置对存活 token 数不敏感。

#### ⚠️ 写代码时撞出来的一条公平性要求：两臂参与旋转的通道数必须相等

G3 的坐标是 **(t,h,w) 三轴**，G4 是 **(t,x,y,z) 四轴**。
若让 G3 空着 z 那批通道不转，**G4 就比 G3 多转一批通道**——
"G4 赢是因为它转的通道多"立刻成为无法排除的替代解释。

**定死**：3 轴时把 z 的份额按比例匀回 t/h/w，两臂**参与旋转的 pair 总数严格相等**，
只是分给了不同数量的轴。`channel_plan(n_axes=...)` 已实现，自测里有断言。
M2 的 PE 侧也是三轴，与 G3 共用同一个 plan。

```
head_dim=128，64 个 rotary pair
  4 轴 (G4/M2 池化侧)  [t=2, x=6, y=6, z=5]  转 19，1D 保留 45
  3 轴 (G3 / M2 PE 侧) [t=3, h=8, w=8]       转 19，1D 保留 45
```

**四个必须定死的实现细节**：

1. **拨哪些通道**：从**高频端**取。高频通道在 2048 长的序列上早已绕圈，
   携带的可用长程信号最少。这条要做消融，不能只凭直觉。
   ⚠️ 另：轴间余数要按**最大余数法**分。初版图省事全丢给第二个轴，
   19 个 pair 分成 `t:1 x:12 y:3 z:3`——x 拿了一大半，凭空造出各向异性，
   而且不报错
2. **坐标归一化**：把 LIBERO 工作空间包围盒按轴映射到 **[0, 16)**——
   与模型预训练时见过的 16×16 网格频率量级对齐。
   米制坐标直接塞进去会频率混叠（`docs/04` §5.4 坑 2）。t 映到 [0, K)
3. **⚠️ 文本起始位置必须与存活 token 数无关**。固定为 `K×256+1`。
   这条直接继承阶段 1 最硬的那个发现：位置编码错了值 **−54 个点**
   （`docs/05` §7.4），比压缩本身（−10.6 点）大五倍。
   若文本起点随池化率浮动，测的就又是位置扰动
4. **深层视觉 token 注意力份额**要监控 —— 对应已测到的 36 点未解释残差
   （`keep=64` 修位置后 34.0%，等长的 `expand@64` 70.0%），
   假设是 token 同质化（`docs/05` §7.6）

### 2.4 深度从哪来：**仿真器回放，不用单目估计**

LIBERO RLDS 只有 `image`/`wrist_image`/`state`，无深度无内外参（已核实
`configs.py:645`、`transforms.py:827`）。上一版打算跑单目深度模型（VLA-4D 用 VGGT）。

**改为：回放动作序列，直接取仿真器深度。** `measure_redundancy.py` 已经在这么做了
（评测确定性保证画面逐帧一致），代码是现成的。

- 只缓存 **patch 级深度：256 个值/帧**，不是全分辨率深度图——
  4D RoPE 要的就是每个 patch 的位置。每 suite 约 **38 MB**（全分辨率要 7.5 GB）
- **必须先验证**：抽 5 条 episode，比对回放 RGB 与 RLDS 里的 RGB。
  对不上就说明回放发散，才回退到单目深度
- 评测时同一模型在线取深度（LIBERO 是同步仿真器，只影响墙上时间不影响成功率）

> **答辩会被问"仿真真值深度是特权信息"**。三层回答：
> ① 真机通常本就有 RGB-D；② 我们的主张是**表示**，不是深度怎么来的；
> ③ 留一个小消融——在子集上换成单目估计深度，看结论是否存活。
> ③ 不进主线，但要留出接口。

## 3. 实验路径：六组，一张表

**全部固定**：LIBERO-Long、K=8、**token 预算 N=256**、20 000 步、n=500 评测、
相同 LoRA 配置。

### 3.0 ⚠️ 先定死 N=256，因为它同时消掉两个混淆

**N=256 = G0 的 token 数。** 这个选择不是随便挑的，它让**每一组都在同一预算上**，
包括单帧基线——于是"历史帧有没有用"和"坐标系哪个好"可以在同一张表里回答。

连带的好处：**G2 与"等预算历史对照"合并成同一组**，少一次训练。

| 组 | 输入 | 池化 | 池化坐标 | PE 坐标 | token | 角色 |
|---|---|---|---|---|---|---|
| **G0** | K=1 | — | — | 1D | 256 | 单帧基线 ✅ Spatial **74.0%**(n=500) |
| **G1** | K=8 | **无** | — | 1D | 2048 | **VLA-4D 类**；上限参考 |
| **G2** | K=8 | **帧独立**，每帧→32 | (h,w) | (t,h,w) | 256 | 粒度对照 **＋等预算历史对照** |
| **G3** | K=8 | **patch 级跨帧** | (t,h,w) | (t,h,w) | 256 | **STTM 类**，一致 |
| **G4** | K=8 | **patch 级跨帧** | **(t,x,y,z)** | **(t,x,y,z)** | 256 | **本方案**，一致 |
| **M2** | K=8 | **patch 级跨帧** | **(t,x,y,z)** | (t,h,w) | 256 | **⚠️ 错配臂**，见 3.0.2 |
| *M1* | K=8 | patch 级跨帧 | (t,h,w) | (t,x,y,z) | 256 | *错配臂，补全 2×2，可砍* |

#### 3.0.1 ⚠️ G1 vs G0 有 token 数混淆，不能用它验证前提

G0 是 256 token，G1 是 2048——**差了 8 倍**。G1 > G0 说不清是历史帧有用，
还是单纯 token 多了 8 倍。**前提检验要用 G2 vs G0**：都是 256 token，
唯一差别是有没有历史。

G1 降级为**上限参考**：它回答"不压缩能到多少"，即 G2–G4 的压缩代价有多大。

> 残留的、无法消除的不对称要写明：G0 的 256 个 token 是**原生未池化**的
> （正是预训练时模型见过的形态），G2–G4 的 256 个是池化产物。
> 这个偏差**方向对我们不利**（偏向 G0），所以是安全的——
> 但不能假装它不存在。

#### 3.0.2 ⚠️ 标题句是强命题，G4 vs G3 只检验了弱命题

§0 的框说的是**"两者必须一致"**（强命题）。
但 G3 和 G4 **两组都是一致的**，只是坐标系不同——所以

```
G4 > G3  只能证明「度量 4D 比图像网格好」   ← 弱命题
         证明不了「一致比不一致好」          ← 强命题，也就是标题句
```

审稿人一问**"那度量池化配别的位置编码呢？"**，我们没有数据。

**修法：把错配臂做出来，构成 2×2。**

| | **PE 用 (t,h,w)** | **PE 用 (t,x,y,z)** |
|---|---|---|
| **池化用 (t,h,w)** | **G3**（一致） | *M1*（错配） |
| **池化用 (t,x,y,z)** | **M2**（错配） | **G4**（一致） |

- **主效应**（列/行）= 弱命题：哪个坐标系好
- **交互项** = **强命题：一致本身是否带来增益**
- 只做 M2 就够撑强命题（G4 > M2 且 G4 > G3）；补上 M1 才是完整的因子设计，
  能报交互项的显著性。**M1 是预算不够时第一个砍的**

> 实现代价很低：**池化代码一行不动**，只换 PE 那一侧传进去的坐标张量。
> §2.2 的 `pool(E, coords, budget)` 接口本来就把两者解耦了。

⚠️ 另有一组**别混为一谈**：`M3 = 度量池化 + MLP 加性编码`（HiST-VLA 那套）。
它检验的是 **RoPE（旋转、相对）vs MLP（加性、绝对）这个机制**，
两边坐标系**仍然是一致的**——所以它回答不了强命题，是另一个问题。
放进 Phase 2 消融，用来答"为什么不用 HiST-VLA 的编码器"。

#### 3.0.3 G2 的规格必须写死，否则 G3 vs G2 是两个变量

早先只写"抽 K′ 帧 + frame-wise 池化"，那样 G3 vs G2 同时含
**帧数不同**与**池化粒度不同**两个变量。

**定死**：G2 = **K=8 全保留**，每帧**独立**池化到 N/8 = 32，总计 256。
于是 G3 vs G2 纯隔离 **patch 级跨帧联合 vs 帧级独立**。

> ⚠️ **要如实说明：这样的 G2 不是 4D-VLA 的忠实复现。**
> 4D-VLA 丢的是整帧（时间分辨率真的损失了），而我们的 G2 保全 8 帧、
> 只是各帧独立压缩。**G2 因此是比 4D-VLA 更强的基线**——
> 赢它更有说服力，但不能在论文里把它标成"4D-VLA"。

#### 3.0.5 实现规格：三件必须写死的事

不写死的话，每一件都会悄悄变成第二个 λ。

**① M2 的网格坐标 = 箱内 patch 的 (t,h,w) 算术均值**

M2 是度量池化、网格 PE。一个度量体素跨多帧时，箱内 patch 的 (h,w) 可能差很远
（同一物体运动导致投影偏移）。

**定死**：三个分量 (t̄, h̄, w̄) 全部取箱内**算术均值**，与 G4 取度量质心
**用同一套平均逻辑、同一份代码**。不要用中位数、投影中心或"取最近帧的位置"——
那会引入新的设计变量，而这个对照的全部价值就在于**池化侧完全相同**。

> ⚠️ 运动物体的箱里，平均出的 (h̄,w̄) 可能落在既不是起点也不是终点的位置。
> **这是预期行为，不是 bug**——它正是"错配"要暴露的退化。
> 代码里加注释，免得后来者"顺手修好"。

**② G2 用与 G3/G4 相同的分箱算法，只是不在 t 轴上分**

G2 是帧独立池化。**不要给它单独写随机采样或均匀裁剪**——那样 G3 vs G2
会同时差"跨帧联合"和"池化算法"两个变量。

**定死**：G2 = 每帧各自在 h–w 平面上分 32 箱、箱内平均，共 8×32 = 256。
与 G3 的唯一差别是 **t 轴不参与分箱**。

**③ ⚠️ G3 的分箱必须真的跨 t 合并，否则 G3 ≡ G2**

这是顺着 ② 推下去撞到的坑，**比前两条严重**：

G3 要把 2048 个 patch 分成 256 箱。若轴划分取 `t:8 × h:8 × w:4 = 256`，
**t 轴每帧一箱 = 完全不跨帧合并**——那 G3 就是 G2，粒度对照测了个寂寞，
而且不会报错，只会得到"G3 ≈ G2"然后被误读成"跨帧联合没价值"。

**⚠️ 2026-08 更正：这一条曾写成"归一化坐标下各向同性分箱，唯一的标量是箱边长"。
代码写出来跑了一遍，这个规则不成立。**（`src/pooling/coord_pool.py`，CPU 自测）

实测：K=8、N=256 下让贪心自由细化，各轴箱数落在

```
G3 (t,h,w)    → [7, 6, 6]      跨帧 token 仅 36/252 = 14%，最大跨度 2 帧
G4 (t,x,y,z)  → [6, 6, 5, 5]   跨帧 token 仅 23/251 =  9%，最大跨度 2 帧
```

**t 轴只有 8 个取值，各向同性会把它推到接近满分辨率，于是两组基本都在做逐帧的
空间池化。** 三个后果连着倒：

1. "静止表面在多帧可见 → 塌成一个带 size 的 token"这个机制**根本没发生**
2. G3 几乎不跨帧 → **G3 ≈ G2**，粒度对照空转
3. §1.2① 的"同一 (h,w) 不同帧可能是不同表面"这个**错误合并机制触发不了**
   → G4 vs G3 也就没什么可赢的，**主实验近乎没有功效**

而这**不报任何错**。原先设计的断言（"存在跨帧 token"）在 14% 下照样通过。

**改用的规则**：

- **t 轴箱数 `n_t` 显式给定**，不交给贪心。默认 `n_t=2`（K=8 时每箱覆盖 4 帧）
- 空间轴仍按贪心细化：每次把当前最粗的轴 +1，**且非空箱数必须真的增加**
  （只判 `≤ budget` 会死循环——箱数超过数据分辨率后占用不再增长，
  贪心永远认为还能细。这个也是跑出来才发现的）
- **`n_t` 不是 λ 那类混淆项**：λ 的问题是两个坐标系量纲不同（米 vs 格）、
  没法取同一个值；`n_t` 是**无量纲整数，G3/G4/M2 取同一个值**，
  并作为消融整组扫描 `{1,2,4,8}` 同时报告两臂曲线。
  要守的规矩是"**没有在两臂之间取值不同的自由参数**"，这条仍然成立

**断言也跟着改**：阈值必须是**比例**（默认跨帧 token ≥ 25%），不能只查 `> 0`。
`assert_cross_frame_merge()` 已实现，自测里有一条专门验证它能拦下 14% 那种情况。

> 这一条是"先写代码再改文档"换来的。纸面上"各向同性"读着很有原则，
> 跑一遍才知道它会让主实验静默失去功效。

### 3.0.4 每一对比较隔离出什么

| 对照 | 隔离出什么 | 若打平意味着 |
|---|---|---|
| **G2 vs G0** | **同预算下历史帧有没有用**（前提检验） | 前提不成立，整个方案要重新解释 |
| G1 vs G2 | 8× token 预算买到了多少 | 压缩几乎无代价（好消息） |
| G3 vs G2 | **池化粒度**：跨帧联合 vs 帧独立 | 跨帧联合没有价值，第一条动机作废 |
| **G4 vs G3** | **坐标系**：度量 4D vs 图像网格 | ⚠️ **弱命题都不成立** |
| **G4 vs M2** | **⭐ 一致 vs 错配** | ⚠️ **标题句（强命题）不成立**，只能降级写弱命题 |
| *G3 vs M1* | *另一侧的一致 vs 错配* | *交互项不显著* |

**必须赢的是 G4 vs G3（弱）与 G4 vs M2（强）这两对。**
弱的赢了强的没赢 → 论文还能写，但故事从"发现一条统一性原理"降级成
"又一个坐标系选择的 ablation"，分量差很多（§6.1）。

#### ⚠️ 全部先用 Phase 1 的最小版本跑

按 §2.2：**零自由超参的坐标分箱池化**，不带 ToMe、不带新颖度打分、
**尤其不带 λ 几何项**——λ 在两个坐标系里量纲不同，各自调优等于给 G4 开小灶。

只有 Phase 1 分出差距之后，Phase 2 的每一项才逐个加上去，
那时它们是**消融表的行**，不再是核心对照的混淆项。

### 3.1 预先登记的预测

1. **G2 > G0**（Long 上，同为 256 token）。依据：Long 是多步、有阶段歧义的任务；
   且本项目自己测到 **Long 的归一化 jerk 是 Spatial 的 18.7 倍**（`docs/05` §4.4），
   轨迹极不平滑正是"不知道自己处在哪一步、反复试探"的症状。
   ⚠️ 用 G2 不用 G1——G1 多了 8 倍 token，赢了也说明不了问题（3.0.1）
2. G3 > G2（同预算下跨帧联合优于帧独立）
3. **G4 > G3**（弱命题），且**收益集中在遮挡/阶段歧义时刻**而非均匀分布 ——
   1.2 ① 预测的正是遮挡场景。**均匀分布的收益是警号**，那更像正则效应。
   ⚠️ 这检验的是 1.2 的 ①③；**②（"更对齐"）本设计证伪不了**，只能作动机
4. **G4 > M2**（强命题）。这是标题句的唯一直接证据
5. G1 > G4，但差距小于 G4 − G2 —— 即 8× 预算买到的，少于坐标系换对买到的。
   **这条若不成立（G1 远好于 G4），说明预算 N=256 卡得太死**，
   要在下结论前补一个 N=512 的点
6. ~~Spatial 上 G2 ≈ G0（单步、基本全可观测，历史帧边际价值低）~~
   **⚠️ 作废**（§4.1 ①）：stride=20 下 Spatial 整条 episode 都填不满历史序列，
   历史全是补帧。这条预测会成立，但成立的原因是序列退化，**同义反复，
   不构成检验**。要保留就得给 Spatial 单独定 stride（≈5）

**分层分析比总成功率更能证伪。** 我们有 per-task 分解和逐步轨迹，做得了。

### 3.2 结果怎么判

| 结果 | 含义 | 下一步 |
|---|---|---|
| G4 > G3 **且** G4 > M2 | 强命题成立 | 主线成立，进消融与写作。补 M1 报交互项 |
| G4 > G3 但 G4 ≈ M2 | **只有弱命题** | 标题句降级成"度量 4D 坐标优于图像网格"。论文还能写，但从"统一性原理"变成"坐标系 ablation"，分量差很多。**先查 M2 是否实现有误**（PE 侧坐标真的换了吗），再认这个降级 |
| G4 ≈ G3 | 弱命题都没有 | **不要马上判死刑，按序排查**：① 坐标归一化尺度失配（2.3 细节 2，最可能）；② 深度质量（回放是否发散）；③ 分箱太粗盖住差异 → 上 Phase 2 的 ToMe 再测；④ N=256 太紧 → 补 N=512。四条排完仍打平，创新点才不成立，转向"池化粒度"次线（G3 vs G2 仍可发表） |

## 4. 开跑前还有四件事

### 4.1 帧间隔 stride —— 最可能造成假阴性

LIBERO 是 20 Hz。K=8 取连续帧 = **0.4 秒**的"历史"，机械臂几乎没动，
八帧近乎同一张图。用它跑 G1 得到"历史没用"是必然的，而那是彻底的假阴性。
Long 的 episode 长 200–500 步 = 10–25 秒，覆盖阶段信息需 **stride ≈ 10–25 帧**。

#### ✅ 已跑（2026-08，pixel 模式，libero_10，episode 平均 388 帧 = 19.4 s）

| Δt(帧) | 秒 | 距离/随机基线 | K=8 覆盖 |
|---|---|---|---|
| 1 | 0.05 | **0.140** | 0.3 s |
| 8 | 0.40 | 0.474 | 2.8 s |
| **20** | **1.00** | **0.692** | **7.0 s** |
| 40 | 2.00 | 0.849 | 14.0 s |

**暂定 stride = 20**（比值落在 0.5–0.8 的区间取中位）。

**顺带证实了当初的担心**：Δt=1 的比值只有 **0.140**——连续帧与"同 episode 随便一帧"
的差距只有 14%，几乎不携带时序信息。原先只是推测"八帧近乎同一张图"，现在有数了。

#### ⚠️ 但这个结果暴露了两件事

**① stride=20 时，除 Long 外的三个 suite 整条 episode 都填不满历史序列**

K=8 × stride=20 要到**第 140 帧**才填得满：

| Suite | 成功 episode 步数 | 历史不完整占比 |
|---|---|---|
| **libero_10 (Long)** | 270 | 36.1% |
| libero_spatial | 106 | **100%** |
| libero_object | 140 | **100%** |
| libero_goal | 103 | **100%** |

这三个 suite 上历史序列**全程都是补帧**（重复最早可得的那一帧），历史帧机制没启动。

→ **§3.1 预测 4「Spatial 上 G2 ≈ G0」作废。** 它会成立，但成立的原因是

## 6. 砍掉了什么，以及什么条件下捡回来

| 砍掉的 | 原因 | 捡回条件 |
|---|---|---|
| **腕部相机** | 引入它只为救「2D 剪枝假设静态相机」这条旧论证，而 1.2 的三条理由在单相机下就成立。代价却极大：token 预算翻倍、K 上限重测、G0 基线重跑 | 主线跑完仍有时间 → 作为"多视角 token 落在同一坐标系可直接去重"的扩展消融。这是纯 2D 方法结构上做不到的事，是加分项不是必需项 |
| **单目深度模型（VGGT 等）** | 仿真器回放能拿真值，代码现成 | 4.2 验证发现回放发散 |
| **训练种子方差（2 组 × 2 seed，24 h）** | 效应大就不影响结论，效应小才需要它 | **G4−G3 落在 ±5 点带内** → 必须补，否则无法判断是不是种子噪声 |
| **G5 假历史对照**（历史帧取自随机时刻） | 它保护的是"历史帧有用"这个前提，不是核心创新 | ⚠️ **条件已收紧**：自建基线比官方低 10.2 点（`docs/05` §8.2），头部空间大，"加东西就涨"更容易发生。**G2 > G0 一旦出现大幅提升就必须补**，用于排除"收益来自更多有效训练/正则"这一混淆。构造以**同 episode 内打乱顺序**为主（只破坏时序结构，保留场景统计），取自其他 episode 为辅 |
| **proportional attention**（ToMe 的 log(size) 偏置） | flash-attn 下无挂载点，要切 sdpa 并逐层包 `LlamaSdpaAttention.forward`，整条对比链含基线都要重跑 | 消融阶段有余力再说 |
| **四 suite 全跑** | 主战场是 Long，Spatial 只作"历史帧在单步任务上价值低"的对照 | 写作时按需补 |

### 6.1 ⚠️ 范围声明：不主张在 LIBERO 上刷 SOTA

**OpenVLA-OFT 已达 95.0%**，其收益来自**动作分块与并行解码，输入侧没有历史帧**。
评审会直接问"为什么不用 action chunking"。

所以主张**不是**"我们把 LIBERO-Long 做得更好"，而是
**固定 token 预算下，度量 4D 的池化 + 位置编码比图像网格的保留更多任务相关信息**——
表示效率的主张，与 OFT 正交，可叠加。

同一条线上还有一个警示：Drop-Then-Recovery 发现 LIBERO 上**移除一半 LLM block，
OFT 反而从 95.0% 升到 98.3%**。既然模型冗余到砍一半层都不掉点，
**"压缩视觉 token 而不掉点"本身就不是有说服力的结果**——
所以核心对照必须是 G4 vs G3（**同预算下谁更好**），而不是"压缩 vs 不压缩"。

**效率是副产品，表示才是论点。**

#### ⚠️ 若只拿到弱命题，论文怎么写

G4 > G3 但 G4 ≈ M2 的情况（3.2 第二行）要提前想好，别到时候硬撑：

| | 强命题（拿到 M2） | 弱命题（只有 G4>G3） |
|---|---|---|
| 标题句 | 池化坐标系 ＝ 位置编码坐标系 | 度量 4D 坐标优于图像网格坐标 |
| 定位 | 一条统一性原理 | 又一个坐标系选择的 ablation |
| 分量 | 可以撑主贡献 | 只够撑一节 |

**弱命题也不是没东西写**——G3 vs G2（跨帧联合 vs 帧独立）与
G2 vs G0（同预算历史帧）都是独立成立的结论。但故事要重写，
不能把弱命题包装成强命题，那是最容易被当场拆穿的一种写法。

## 7. 风险

1. **⚠️ G4 ≈ G3** —— 弱命题都不成立。最致命，所以排在 11 月而不是最后。
   次线（G3 vs G2 的粒度结论）能救回一部分
1b. **⚠️ G4 ≈ M2** —— 弱命题成立但**强命题不成立**，标题句要降级（§6.1）。
   风险不小：很可能 PE 用什么坐标的影响大于"是否与池化一致"。
   **提前想好降级后的写法，别临时硬撑**
2. **⚠️ novelty 表述被打** —— 见 1.1。三条硬事实必须自己先写进 related work，
   而不是等审稿人指出来
3. **stride 选错导致假阴性**（4.1）—— 最便宜也最容易漏的一条
4. **深度回放发散**（4.2）—— 有回退方案，只是变贵
5. ~~多帧基线跑不动~~ —— 已排除，K=8 不压缩开检查点 21.2 GB
6. **⚠️ 训练流程复现不到官方水平** —— 曾记为"已排除"，**满量评测推翻了它**：
   自建 step20000 = **74.0%**，官方 = **84.2%**，−10.2 点，**p=7.3e-05**
   （`docs/05` §8.2）。n=50 时的 72.0% vs 76.0%、p=0.65 是子集难度偏差造成的假象。
   **内部有效性不受影响**（五组共用同一配方，偏移抵消），
   但绝对数字不能与文献并列，且头部空间变大会让"加东西就涨"更容易发生
   —— **若 G2 vs G0 出现大幅提升，被砍掉的 G5 假历史对照必须捡回来**（§6）

**下一个决策点**：**G2 vs G0**（同预算下历史帧有没有用）。前置三件做完即可开跑。
⚠️ 不是 G1 vs G0——那一对差了 8 倍 token，赢了也说明不了问题（3.0.1）。

但冻结模型没见过多帧输入，**这一步开始必须训练**。

需要做的：

   HF 上的 `openvla/modified_libero_rlds`。

4. **基线微调**：K=1 复跑一遍 LoRA，确认我们的训练流程能复现官方 checkpoint 的水平

### 显存实测结果（2026-08，已完成）

`scripts/probe_vram.py --sweep`，RTX 4090 24 GB，flash-attn 2.5.5，
LoRA r=32 all-linear，batch=1。峰值显存（GB）：

| 配置 | K=1 | K=2 | K=4 | K=8 | K=16 |
|---|---|---|---|---|---|
| 推理，不压缩 | 15.4 | 15.6 | 15.9 | 16.7 | 18.2 |
| 推理，keep=96 | 15.2 | 15.3 | 15.5 | 15.8 | 16.3 |
| 训练，不压缩 | 18.2 | 20.3 | **OOM** | OOM | — |
| 训练，不压缩 + 梯度检查点 | — | — | 18.5 | **21.2** | OOM |
| 训练，keep=96 | 17.2 | 18.2 | 20.4 | **OOM** | — |
| 训练，keep=96 + 梯度检查点 | — | — | — | **20.1** | OOM |

权重本身占 15.13 GB，留给激活的全部预算只有约 8.6 GB。

**① 预测错了：不压缩的 K=8 基线跑得动。**
先前判断"要对照的那个基线是最跑不动的那个"，只在不开梯度检查点时成立，
而那不是实际会用的配置。**"压缩是使能而非优化"这个说法在 24 GB 卡上不成立**，
不采用该叙事。好消息是核心对照实验（阶段 C）能在 4090 上做，不必租大卡。

**② 真正的杠杆是梯度检查点，不是压缩。**
K=8 时压缩与不压缩只差 1.1 GB（20.1 vs 21.2）——检查点已经把 LLM 的激活
消掉了大半，压缩再省的空间有限。压缩换来的是**速度**（检查点本身要付
30–40% 吞吐，序列短也更快），不是显存。

**③ token 数不是全部——这条给出一个设计决定。**

- K=2 × keep=256 = **512** token → 20.3 GB
- K=4 × keep=96 = **384** token → 20.4 GB

token 更少反而更费。因为**压缩发生在视觉主干之后**：K 帧要各过一次
DINOv2+SigLIP，每次的激活都要留着反传，这部分与压不压缩无关。
两点粗算（仅供定量级参考）：每帧视觉主干约 **0.5 GB**，LLM 约 **6.25 MB/token**，
keep=96 时视觉那部分占每帧成本的四成多。

→ **视觉主干应当冻结，不挂 LoRA。** 官方 `finetune.py` 用
`target_modules="all-linear"`，LoRA 会挂到视觉主干上，多帧时这笔开销乘 K。
冻掉它既省显存，也更贴合本方案——我们改的是 token 表示与位置编码，
不是特征提取器。

## 阶段 C · 前置控制：历史帧到底有没有用

> 本阶段由一个提问补上：**若视觉主干冻结、只是把多帧特征合并送进 LLM，
> 视觉特征本身没有变好，历史帧凭什么弥补单帧的判别缺陷？**

### C.1 先把概念说清楚：历史帧不修复特征质量

**它确实不能。** 若 DINOv2+SigLIP 在第 t 帧分不清红杯子和橙杯子，
t−1…t−7 帧里同一个静止杯子的特征同样分不清；合并一堆同样糟糕的特征，
得到的还是同样糟糕的特征。凡是宣称"多帧提升视觉判别力"的说法，
除非动了编码器，否则站不住。**本项目不作此主张。**

历史帧提供的是**任何单帧都不包含的信息**，与特征质量是正交的两个轴：

| 来源 | 为什么单帧拿不到 |
|---|---|
| **只能由变化观测的状态** | 同一个半开的夹爪，"正在闭合"与"正在张开"的图像可以完全一样。速度、方向、"刚抓住还是刚脱手"都属此类 |
| **遮挡与记忆** | t−5 帧可见、t 帧被机械臂挡住的物体。当前帧不含它，编码器再好也编不出来 |
| **多步任务的阶段消歧** | "把碗放进抽屉再关上"——"正要开抽屉"与"刚放完碗"的画面可以几乎一致，区分它们需要知道自己刚做过什么 |

一句话：**历史帧补的是信息的可得性，不是特征的判别力。**

### C.2 ⚠️ 这个提问暴露的真实缺口

**我们从未验证过历史帧在 LIBERO 上是否有用。**

OpenVLA 是单帧模型，Spatial 拿到 84%。若 K=8 加上池化仍是 84%，
等于什么都没做。而原先的阶段 C（2D 池化 vs 4D 池化）**默认了多帧优于单帧**——
前提若不成立，就是在比较两种压缩废物的方法。

因此这组控制实验必须补，且**排在 2D vs 4D 之前**。

### C.3 实验设计

| 组 | 配置 | 目的 |
|---|---|---|
| C-1 | K=1（自建配方，已完成，Spatial 72.0%） | 单帧参照 |
| C-2 | K=8 不压缩，**LIBERO-Long** | 历史帧到底有没有用 |
| C-3 | K=1，**LIBERO-Long** | Long 上的单帧参照 |
| C-4 | K=8 不压缩，Spatial | 验证「单步任务里历史帧价值低」的预测 |

**为什么主战场是 Long 而非 Spatial**（预先登记的预测）：

C.1 的三条机制里，Spatial / Object / Goal 大多是**单步、基本全可观测**的任务，
历史帧的边际价值本就低。预期效应最大的是 Long——多步、有阶段歧义。
而 OpenVLA 恰恰在 Long 上最弱（52%）。

本项目自己的数据独立支持这一判断：**Long 的归一化 jerk 是 Spatial 的 18.7 倍**
（`docs/05` §4.4）。轨迹极度不平滑，正是"不知道自己处在哪一步、反复试探"的症状。

**预测**：Long 上 C-2 显著优于 C-3；Spatial 上 C-4 与 C-1 差异不显著。
若两个 suite 上历史帧的收益一样大，说明它带来的不是时序信息而是别的东西
（比如等效于数据增强），那对本方案的叙事是坏消息，需要重新解释。

### C.4 三种结果的走向

| 结果 | 含义 | 下一步 |
|---|---|---|
| Long 上 K=8 显著更好 | 前提成立 | 进入阶段 D（2D vs 4D 池化） |
| 两个 suite 都打平 | LIBERO 测不出时序推理，**或**模型没学会用历史 | 后者指回位置编码——先给多帧加 4D RoPE 再测一次；仍打平则换基准或换方向 |
| Long 上 K=8 反而更差 | 更长的序列在没有正确位置编码时是负担 | 与阶段 1 的发现一致，直接进 4D RoPE |

注意后两种都不是死路：它们把矛头指向位置编码，而那正是本项目已量化过的地方
（位置修正值 +54 点，压缩本身只值 −10.6 点，见 `docs/05` §7）。

### C.5 与阶段 1 发现的连接

历史帧的信息要被用上，模型必须能分辨每个 token **来自哪一帧、在哪个位置**。
阶段 1 已经量化了这件事的重要性：位置编码错了值 −54 个百分点。

所以「多帧 token 需要 (t,x,y,z) 坐标」不是设计偏好，是实测支持的推论。

**冻结视觉主干在这个叙事里反而是干净的**：我们不声称改进了视觉表征，
我们改的是**模型索引时空信息的方式**——而这恰好可以在冻结编码器的前提下做。
这也让贡献的边界清晰：任何收益都不能归因于"更好的特征"。

## 阶段 D · 2D 池化 vs 4D 池化（核心创新验证）

> 仅在阶段 C 确认历史帧有用之后才做。

`docs/04` §7 列的核心对照：**固定 token 预算**，比较

- 2D 池化：每帧独立压缩（对应现有的一堆 token pruning 工作）
- 4D 池化：跨帧联合压缩，合并 token 带 (t, x, y, z) 坐标

这是唯一能证明"在 4D 上做"不是包装的实验。
**若两者打平，方案的创新点就不成立**，要及早知道，所以排在 4D RoPE 之前。

预期能用上的杠杆（`docs/04` 4.5）：同一物理位置在多帧都静止 →
合成一个带时间区间的 token。这个如果成立会是最漂亮的点。

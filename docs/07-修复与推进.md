## 1. 已复现的缺陷

旧版 `quantile` 有两套不一致的时间边界：`_resolve_bins` 用固定时间箱估计占用数，
`_quantile_assign` 随后又按有效帧重新计算时间分位数。历史不足时，一套认为只有一个
时间箱，另一套分成两个，实际非空箱数超预算；按箱排序截断后，最新帧可能全部丢失。

CPU 实测条件：K=8、stride=16、budget=256、n_t=2、enforce_n=0，16×16 规则网格，
左侧补帧、有效帧在右侧。G3 与 M3 共用该网格分组路径。

| 真实历史帧数 | 旧 G3 最新帧保留 patch | 修正版 G3 最新帧保留 patch |
|---|---:|---:|
| 1 | 256 | 256 |
| 2、3、4 | **0** | **256** |
| 5、6、7、8 | 256 | 256 |

stride=16 时，真实帧数 2–4 对应策略时刻 16–63（从 0 计，不含初始等待）。
修正版在本探针的 1–8 个有效帧条件下保留全部有效输入 patch；G2 分组与旧版逐位一致，
完整 8 帧的 G3 分组也逐位一致。证据：
[旧版](../results/tables/pooling_audit_grid.json)、[修正版](../results/tables/pooling_audit_fixed.json)。

这些结果证明输入处理存在缺陷，**不能证明此前成功率差距全部由它造成**。
真实度量坐标上的预算占用仍需另测；本探针不能代表视觉语义信息损失。

## 2. 修复的边界

新增 `--partition quantile_fixed`：固定时间轴/指定分组轴，自由空间轴继续等量分箱。
训练与评测默认使用 `quantile_fixed`；复现旧 checkpoint 须显式选择 `quantile`。
下面的挂点检查、训练与评测命令均显式指定修正版，避免依赖各入口默认值。

新修正版应从基础模型启动独立训练。直接给旧 checkpoint 换算子评测只能标为
“推理干预诊断”，不能替代匹配训练的对照，也不能混进历史 2×2 主表。
撤回此前“继续完成旧 G3-full”的资源建议。若服务器确认仍在跑旧算子，保存已有
checkpoint、配置与日志后停止该任务，不再为它投入完整评测。这里未连接服务器，
不代表已停止进程。旧结果保留作缺陷诊断；与 G2 的比较及旧四格效应分解暂停作为
方法结论，§13.8 的旧 G3-full 判读表不再驱动当前决策。

已合并远端 e7b80b9 的默认值翻转、回归测试修正和 §13.9，合并后 31 项测试通过。
下面命令仍全部显式指定 partition。历史无后缀目录不能
据新默认解释为 fixed；判定算法以当时配置和代码为准，缺证据时标记未知。

还有三项保留的问题：

- **深度与增强对齐**：训练 RGB 随机裁剪与缓存 patch 深度未同步。修改评测中心裁不能
  修复训练时的错位；需要全分辨率深度及同步变换后再做新的度量四格。
- **有效 token 数**：固定 256 输出槽不等于 256 个有效 token。空槽仍参与注意力，
  `enforce_n` 不保证输入非空箱不足时没有空槽。此次不同时更改注意力和分箱以免混淆。
- **预算搜索**：非空箱占用数不一般满足单调性；现有搜索及可选局部扫描不是全局最优保证。
  此次修复专门解决固定轴边界不一致，不声称解决所有分箱问题。

## 3. 现在按这个顺序做

### A. 本地与服务器都可先做的结构检查

在项目根目录、已激活 Python 环境中运行：

```bash
python scripts/project_doctor.py --out results/project_status.json
python -m unittest discover -s tests -v
python scripts/audit_pooling.py --partition quantile
python scripts/audit_pooling.py --partition quantile_fixed
```

张量测试需要 torch。没有 torch 时 unittest 会跳过该组，不能把跳过算作通过。
doctor 只查文件、语法及版本，不证明 CUDA、EGL、模型前向或训练可用。
先在训练服务器归档实际存在的 checkpoint、逐局日志及配置，不能由文档推断进程仍在运行。

### B. 只启动一个修正版 G3 冒烟任务

先激活现有 OpenVLA 环境、设置已有 `OPENVLA_ROOT`，确认数据目录实际存在。
以下沿用项目服务器文档中的数据目录；若服务器不同，只修改数据路径。

```bash
python scripts/check_wire.py --arms G3 --partition quantile_fixed --offline
python scripts/finetune_kframe.py \
  --arm G3 --K 8 --stride 16 --budget 256 --n_t 2 \
  --partition quantile_fixed --no_subset True --micro 8 --seed 7 \
  --data_root_dir /root/autodl-tmp/datasets/modified_libero_rlds \
  --bench_only True --run_id_note fixed-smoke
```

`--offline` 使用已有默认 Spatial 模型缓存；缓存不在时用 `--ckpt` 指已有模型目录。
冒烟验收：挂点检查成功退出、loss/梯度无非有限值、10 个有效更新完成、内存和吞吐可接受。
挂点检查使用合成/缓存输入，只验证连接；它不是任务成功率测试。

### C. 通过后跑独立训练，再做闭环

同样命令去掉 `--bench_only True`，把 note 改为 `fixed-main`；其余参数保持一致。
默认目标 30000 步。中断后在**同一条正式命令**后加 `--resume_from auto`；
不要省略 `--no_subset True`、`--partition quantile_fixed`、seed 或 note。
新旧 run ID 已分开；保存 checkpoint 时先写临时目录，必要文件齐全才发布 step 目录。

从 doctor 的实际列表复制新 checkpoint 路径，再运行（先设置 ADAPTER）：

```bash
test -n "$ADAPTER" && test -f "$ADAPTER/adapter_config.json" || exit 1
python scripts/run_eval_kframe.py \
  --arm G3 --K 8 --stride 16 --budget 256 --n_t 2 \
  --partition quantile_fixed --adapter "$ADAPTER" \
  --task_suite_name libero_10 --center_crop True --seed 7 \
  --num_trials_per_task 50 --eval_batch 8 --run_note fixed-main
```

先检查少量任务能跑通，再按固定协议补齐全部任务；如果分段，每段明确 start/end，
使用相同配置和 note，避免重叠。不要根据先看到的成功率挑任务或延长训练。
完整十任务为主结果；历史去 task1 的九任务口径同时报告并说明，不能临时改变排除规则。

**本轮资源上限是一个 G3 正式训练及其评测**，约 25 h 训练为用户提供的估计，
以服务器实测为准，不预先承诺四臂约 100 h。训练前核对已有 G2-full 的数据、增强、
步数、基础模型、种子和评测初始状态；能核验且匹配就复用，不能核验则只作历史参照。
不要为追求复用而猜填旧元数据。完整十任务为主口径；相同初始状态的逐局差值可配对，
但单个训练种子的区间不代表训练随机性的稳定性。

看完这一次完整结果再决策：

- 若 G3 有改善且具实际价值，再做匹配 G2/G3 的确认对照；不自动恢复四格。
- 若 G3 与 G2 接近，优先保留更简单、稳定、成本更低的方案，不为追求正结果扩展模块。
- 若 G3 仍明显较差，停止这条全局跨帧池化路线。只有明确失效证据指向预算分配时，
  才考虑一个“当前帧保底、历史使用剩余预算”的变体，先做低成本探针，再决定训练。

G2/G3 只检验帧独立与跨帧聚合，不能单独证明“历史优于单帧”。若最终保留后者作为
成果命题，需要可比的单帧对照；这不属于本轮新增训练承诺。度量几何收益同样留待
后续独立验证。bug 修复属于实验有效性工作，不能替代方法贡献。

## 5. 与申报方向的关系

保留多帧感知、几何信息和操作任务这条主线。当前工程实现是 OpenVLA 的历史输入与
位置/池化研究；它尚不等于申报中的完整 4D 编码器、时间动作输出、规模化自建数据及真机系统。
将“可复现仿真基线＋明确对照＋一项有证据的改进”作为近期成果；更大交付需要单独排期。
现有负结果只能约束当前实现，不能据此宣布 4D 具身感知方向失败。

本轮先完成 CPU 张量回归、工程修复与执行方案，随后完成 §4.1 的 GPU 正式训练及
checkpoint 完整性检查和 §4.2 的 LIBERO 闭环评测。真机实验仍待服务器验证。
参考论文 PDF 不在本轮逐页重审范围内。

本地验证环境：Windows、torch 2.2.0+cpu、numpy 1.26.4。31 项 unittest 全部通过，
无跳过；coord_pool、wire、rope4d、kframe、depth_cache、subset_filter、camera、runs
八个模块的内置自检通过；56 个 Python 文件通过 Python 3.10 语法检查。
修改后的 setup_server.sh 通过 `bash -n`，Git 差异无空白错误。

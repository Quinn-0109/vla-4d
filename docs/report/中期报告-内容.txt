H1 一、摘要

P 本项目在 OpenVLA-7B 上研究一个问题：在视觉 token 预算固定的前提下，如何利用历史观测改善机器人操作。所谓预算固定，指多帧输入经压缩后进入语言模型的视觉 token 数与单帧相同（N = 256），因此任何收益都不能由“多喂了 token”来解释。我们在 LIBERO-Long 上完成了三组可比对照的完整训练与满量评测，每组 500 局。

P 主要结果（同一训练条件：30 000 步，n = 500，eval_batch = 8）：

L 单帧基线 G0：**23.40%**
L 帧独立多帧池化 G2：**42.20%**，相对 G0 **+18.80 点**
L 跨帧联合池化 G3（修正算子后）：**23.60%**，相对 G0 **+0.20 点**，相对 G2 **−18.60 点**

P 结论有两层。第一层是正面的：在预算固定的条件下引入历史观测确实有效，收益接近 19 个百分点。第二层是负面的，也是本阶段最主要的发现：**把所有帧放进一个全局预算里竞争的这种聚合方式，会把历史观测带来的收益几乎全部吃掉**——G3 与单帧基线的差距只有 0.20 点。项目据此按事前写定的规则停止了跨帧联合池化路线，改以较简单的帧独立方案推进软件交付，并把缺陷修复与失败分析作为工程与方法学产出保留下来。

P 有两条限制必须与上述结论同时出现，不能省略。其一，G2 与 G3 比较的是**聚合方式**，它本身不能证明“历史优于单帧”，支持后者的是 G0 与 G2 的对照。其二，发现并修复输入处理缺陷属于**实验有效性**工作，不能替代方法贡献。

H1 二、研究问题与路线设计流程

H2 2.1 命题的收缩

P 申报方向是 4D（三维空间加时间）时空感知用于机器人操作。这个方向作为整体不可直接检验，必须收缩到能被单次实验否证的命题。收缩的路径是四步：

L **固定可控变量**：底座模型、任务集、视觉 token 预算（N = 256，与单帧的 256 个 patch 相同）。
L **把“4D 有用”拆成互相独立、可分别检验的层**，见 2.2。
L **每一层配一个能证伪它的对照臂**，见 2.3。
L **在开跑之前写下判据、样本量与决策规则**，见 2.4。

P 当前命题定稿为：**固定视觉 token 预算下，怎样保留当前观测，并利用历史观测改善机器人操作？** 它是一个待检验的问题，不预设跨帧池化或度量坐标一定更好。这一点在本阶段得到了回报：由于命题没有预设方向，否证结果同样是可报告的结论，而不是“实验失败”。

P 把方向拆成四层的好处是，某一层被否证不会连带否掉其余各层，也不会让整条路线陷入要么全对要么全错。

H2 2.4 事前登记：判据先于结果

P 每一次主实验开跑之前，判据表、样本量估计与决策规则先写进实验记录，再启动训练。理由是这类实验最难发现的失败不是“结果错”，而是**判据错**：看到数以后再定阈值，任何结果都能被解释成成功，而且事后无法自查。

P 本项目已执行两次事前登记。第一次规定了 2×2 的读法（主口径为 10 任务，同时报告排除 task 1 的 9 任务口径，不得看到结果后临时换口径）。第二次规定了修正版 G3 的资源阈值为 9 任务口径 33%，并写明三种结果各自对应的动作。第二次登记在 9 月 20 日直接触发了停止决策——这正是事前登记的作用：**停止是按规则执行的，不是事后找理由**。

H1 三、系统实现

H2 3.1 数据侧：带间隔的 K 帧窗口

P 官方 RLDS 数据管线只支持连续窗口，我们替换了分窗函数以支持带间隔的历史采样（K = 8，stride = 16）。窗口开头历史不足时重复最早一帧，并置补帧掩码。帧间隔由实测确定：以特征距离比值落在 0.5 至 0.8 带内为判据，带内取最小值以减少补帧。

H2 3.2 模型侧：一份接线产生全部对照

P 三个挂载点：视觉主干（K 帧分块前向）、投影器（池化并给出位置编码所需坐标）、每一层的 rotary_emb（4D RoPE 采用扩展式，不替换原有 1D 通路）。池化算子定稿为**等量分箱**，在图像网格坐标上与均匀体素逐位等价，在真值深度上把预算占用从 240 提到 256，约 6%。

P 池化的位置处理来自阶段 0 的一个实测结论：把压缩后 token 的位置还原为其成分 patch 的质心，成功率从 18.0% 提升到 72.5%，提升 54 个百分点。这说明**压缩掉的分主要来自位置偏移，而不是信息损失**，也正是“用坐标来组织压缩”这一设计的出发点。

P 接线的正确性在真 7B 上验过四项，其中两项可证伪：改变深度输入时 G4 的输出变化而 G3 精确不变；G4 与 M2 的 logits 不同。前者证明度量坐标真的进了模型，后者证明位置编码侧的坐标真的起作用。

H2 3.3 评测侧

P LIBERO-Long 10 个任务，每任务 50 个确定性初始状态。两项工程优化：视觉特征缓存（视觉主干冻结，同一帧的特征逐位相同，已用逐位对拍验证，整体省约 20% 时间）与批量评测（eval_batch = 8）。逐局成功与否落盘为 JSONL，这是配对检验的唯一输入——一旦聚合成任务级成功数，配对表中的两个不一致格就再也恢复不出来。

H2 3.4 来源记录与可复现性

P 训练输出 run_config.json 与 sessions.jsonl；评测输出与日志同名的元数据文件，记录参数、本地源码哈希、adapter 权重 SHA-256、动作统计量与初始状态哈希。完整 checkpoint 路径与配置参与日志身份，因此同名 step 的不同模型不会互相覆盖；默认拒绝覆盖已有记录，包括半成品记录。

H2 4.3 预算翻倍后的稳健性

P 为检验 L0 不是只在欠训点成立，我们在 50 000 步上重复了 G0 与 G2：31.8% 提升到 48.0%，差 16.2 点，z = 5.31，p = 1.1e-7，置信区间 [10.2, 22.2]。事前阈值为不低于 10.7 点、判的是点估计，通过；但**区间下界 10.2 略低于阈值，因此不能说连区间下界也过了**。另外 G2 在 50k 步上的 48.0% 追平了官方在同一链路上的 48.2%，而我们冻结了视觉主干、训练样本量约为官方的 1/53。

H2 4.5 一次缺陷的发现、修复与复测

P **发现。**旧分箱实现存在两套不一致的时间边界：一处按固定时间箱估计占用数，另一处随后按有效帧重算时间分位数。历史不足时，前者认为只有一个时间箱，后者分成两个，实际非空箱数超出预算；按箱排序截断后，最新一帧可能被整帧丢弃。

P **复现。**在 CPU 上以 K = 8、stride = 16、N = 256、n_t = 2 复现：真实帧数为 2、3、4 时，最新帧保留的 patch 数为 0/256，对应 episode 的第 16 至 63 步。帧独立的 G2 不受影响，因为它的输出槽不跨帧。

P **修复。**新增固定时间轴与分组轴的分箱模式，自由空间轴继续等量分箱。完整 8 帧情形以及 G2 的分组与旧版逐位一致，只改变历史不足时的行为。默认已切换为修正版，复现旧 checkpoint 须显式指定旧算子。

P **复测，以及一次归因撤回。**我们从底座重新独立训练了修正版 G3（30 000 步，29.92 小时，RTX 4090，峰值显存 18.99 GB），并使用全量数据，比原先多约 50%。结果是 24.00% 降到 23.60%，**没有回升**。因此我们撤回了此前写下的归因假设“补帧期丢最新帧解释了跨帧家族的缺口”：缺陷是真的，但不是主因。

P 这一段是本阶段方法学上最有价值的部分。一个真实缺陷加一个看起来自洽的解释，如果不做独立复测，很容易被写成“修好了就好了”，而实际的因果并不在那里。

H2 4.6 统计功效的硬上限

P LIBERO 的 n = 500（50 个初始状态 × 10 个任务，确定性评测）是**硬上限**，无法通过多跑几遍来增加。按实测不一致率反推，检出 1.78 点需要 n 约 8358，检出 3 点需要 n 约 4300。因此 L1 与 L3 的“未能证实”不等于“证伪”，这一句必须与结论同时出现。

P 另有一处事前估计被实测修正：配对检验的收益远小于预期。G3 与 G4 的不一致对为 152/450 = 33.8%，配对标准误只从 2.98 降到 2.74，即降低 8%，而非事前假设的 35%。两臂逐局几乎独立，配对没有多少方差可消。我们的分析脚本因此**逐对打印配对标准误**——不打印它，就会误以为做了配对所以更灵敏。

H1 五、方法论：把静默失败当作一类工程问题

P 本项目最常见的错误不是崩溃，而是“参数没传到但一切正常”：不报错、loss 照降、成功率照样给出一个数。针对这一类失败，已固化以下做法。

L **结论台账。**所有结论集中在一处并注明出处，其他文档只引用不复述。此前同一个数在三处各写一遍，已经导致过版本记错。
L **撤回记录。**写过又被自己数据推翻的结论单列一张表，目前二十余条。例如“n = 50 够用”（曾三次误导本项目，实际只能检出 25 个百分点以上的差异）、“动作 token 准确率能判模型强弱”（不仅弱，而且会反向）、“2.7 倍压缩免费”（跨任务集复现后是 −10.6 点，p = 1.6e-3）。
L **判据本身要被检验。**例如曾以“序列长度应为 302”判断位置编码是否退化，后发现序列长度随语言指令抖动、与对照臂无关；真判据是位置编码的轴数，现已写成断言。
L **硬拦而非兜底。**缺相机参数、未设置批次、对照臂定义未定、评测记录已存在等情形一律抛错，不静默走默认路径。空字符串参数也单独拦截，因为它是 falsy，会静默变成“评测底座模型”并给出一个看起来正常的成功率。
L **回归测试。**目前 53 项全部通过，覆盖分箱缺陷的复现与修复、诊断开关不改变被测量、来源身份不因诊断开关而改变、导出 schema 的版本与缺字段报错等。缺 PyTorch 的机器上会跳过 7 项张量测试，**跳过不计作通过**。

P 这套做法本身是可交付的经验：它不产生新的成功率，但它是上面每一个数字可被信任的原因。

H1 六、当前结论与其边界

P **定稿表述（引用时照此表述）：**在现有实验条件下，帧独立多帧方案优于单帧基线；修正版跨帧联合池化未获得进一步收益，并低于历史帧独立参照。项目据此选择较简单的方案推进软件交付，同时保留输入缺陷修复与失败分析。

R n = 500 是硬上限|“未能证实”不是“证伪”，须与效应量所需样本量一起写
R 空槽预算未拉平|G3 与 M3 用 242 个槽、M2 与 G4 用 256 个，差 5.5%，方向有利于 G4。拉平开关已实现但默认关闭，启用需四臂一起重训
R RGB 裁剪未同步到深度与射线|世界系 1.4 至 2.8 cm，约为分箱宽度的 1/9，方向不利于度量臂。训练侧的随机裁剪无法靠加开关修复，需重建全分辨率深度
R 每臂只有一个训练种子|以固定测试集上的实测差值为主，不把二项抽样区间解释为训练随机性的证据
R G0 与 G2 的训练来源不完整|可复现的是“该 checkpoint 达到 X”，不是“重新训一遍还能得到 X”

H2 7.4 决策门的三种结果

P 阶段 D 完成后只做一次判断，三种结果各自对应的动作已写定：

L **若证据支持跨帧混合稀释了当前状态**：只提出一个受限改版——为当前帧预留独立 token 配额，其余预算分给历史，并继续保留帧身份。先写设计、单元测试与离线分配对照；是否训练另行审查，**绝不自动启动**。
L **若六个案例没有一致的机制信号**：停止方法扩展，写成“当前证据下无法定位单一机制”，进入材料收口。
L **若新的导出链路本身不可靠**：只修工具并重采同样的六局，**不增加任务或 episode 数**。

P 任何候选改版在申请训练资源前都必须说明：它会改变最终系统、主结果表或演示中的哪一项。无法说明则不训练。

H1 八、风险与未决问题

L **机制尚未解释。**跨帧联合池化为什么把收益吃光，目前只有假设没有证据。计划的诊断是低成本的，但需强调：“每帧分到多少 token”不是天然存在的量，跨帧的一个输出槽由多帧共同构成。我们采用按 patch 计数的分数归属作为定义，换一种归属方式数就会变，因此**结论必须连同定义一起报**。
L **诊断可能得不出结论，这已被写进决策门。**阶段 C 只采 18 个 arm-case，样本量不支持任何统计判断；如果六个案例没有一致的机制信号，按事前规则就写成“当前证据下无法定位单一机制”并进入材料收口，**而不是加大样本去找一个解释**。
L **诊断的解释力有边界。**分配统计给机制线索，不能单独证明“成功率下降就是因为某一项”；若使用专家演示窗口，结论只能限定在专家轨迹上。
L **L2 未做。**它是四层里唯一没有排期的一层，成本低且新意明确，作为有提前量时的第一候选。
L **历史来源不可补。**G0 与 G2 的训练种子与来源元数据无法恢复，只能标记为历史配置不可核验。
L **环境风险。**训练服务器为容器环境，约每 22 小时重启一次，长训练必须支持从同一 run 自动续训；此前已有训练在 27 000 步附近被中断的记录。

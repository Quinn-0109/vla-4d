H1 一、项目概述与主要结果

P 本项目研究一个问题：在视觉 token 预算固定的前提下，如何利用历史观测改善机器人操作。预算固定的含义是，多帧输入经压缩后进入语言模型的视觉 token 数与单帧相同（N = 256），因此任何性能变化都不来自“多喂了 token”。

P 围绕这一问题，我们在 OpenVLA-7B 上实现了完整的多帧视觉输入链路，并在 LIBERO-Long 上完成了三种方法的独立训练与满量闭环评测，每种方法 500 局。

P 两点结论。其一，**在预算固定的条件下引入历史观测是有效的**：帧独立多帧方案比单帧基线高出 18.80 个百分点。其二，**聚合方式决定了这份收益能否保留**：让八帧在一个全局预算中共同竞争的跨帧联合池化，其成功率与单帧基线基本持平（+0.20 点），历史观测带来的增益没有被保留下来。

P 项目据此选择帧独立方案作为软件交付的主线，并把当前阶段的工作集中在三件事上：用小样本固定案例诊断跨帧聚合的机制、做出可回放的最小演示、完成结项材料。

H1 二、研究问题与技术路线

H2 2.1 命题

P 申报方向是 4D（三维空间加时间）时空感知用于机器人操作。为使其可实验检验，我们把它收缩为一个具体命题：**固定视觉 token 预算下，怎样保留当前观测，并利用历史观测改善机器人操作？**

P 收缩的方法是四步：固定可控变量（底座模型、任务集、token 预算）；把“4D 有用”拆成互相独立、可分别检验的假设层；为每一层配一个能够否证它的对照臂；在实验开始之前写下判据、样本量与决策规则。命题本身不预设跨帧池化或度量坐标一定更好，因此任一方向的结果都是可报告的结论。

H2 2.2 四层假设

P 分层的作用是使结论可定位：某一层的结果不会连带决定其余各层。

H1 三、系统实现

H2 3.1 数据侧：带间隔的 K 帧窗口

P 官方 RLDS 数据管线只支持连续窗口，我们替换了分窗函数以支持带间隔的历史采样（K = 8，stride = 16），窗口开头历史不足时重复最早一帧并置补帧掩码。帧间隔由实测确定：以特征距离比值落在 0.5 至 0.8 带内为判据，带内取最小值以减少补帧。

H2 3.2 模型侧：一份接线产生全部对照

P 共三个挂载点：视觉主干（K 帧分块前向）、投影器（执行池化并给出位置编码所需坐标）、每一层的 rotary_emb（4D RoPE 采用扩展式，保留原有 1D 通路）。池化算子为等量分箱，在图像网格坐标上与均匀体素逐位等价，在真值深度上把预算占用从 240 提高到 256。

P 池化的位置处理来自前期的一项实测结论：把压缩后 token 的位置还原为其成分 patch 的质心，成功率从 18.0% 提高到 72.5%。这说明压缩带来的性能损失主要来自位置偏移而非信息丢失，也是“用坐标组织压缩”这一设计的出发点。

P 接线在真实 7B 模型上通过四项检查，其中两项具有证伪能力：改变深度输入时 G4 的输出随之变化而 G3 精确不变，说明度量坐标确实进入了模型；G4 与 M2 的 logits 不同，说明位置编码侧的坐标确实起作用。

H2 3.3 评测侧

P LIBERO-Long 10 个任务，每任务 50 个确定性初始状态，构成 500 局的满量评测。两项工程优化：视觉特征缓存（视觉主干冻结，同一帧的特征逐位相同，已用逐位对拍验证，整体提速约 20%）与批量评测（eval_batch = 8）。每局的成功与否单独落盘，因此任何两种方法之间都可以按相同初始状态做逐局配对分析。

H2 3.4 诊断与演示工具

P 为支撑机制分析与结项演示，本阶段实现了一套默认关闭的只读记录能力，开启后不改变评测路径、随机数顺序与成功判定：

L **轨迹导出。**逐步记录动作、环境步、成功状态、八个历史帧的来源步编号与关键帧图像，采用逐行可恢复格式并原子发布，带 schema 版本，读取器对缺字段给出明确错误。
L **token 来源统计。**记录每个输出 token 的来源帧、贡献 patch 数与权重，由此可得最新帧的贡献质量、仅由最新帧构成的 token 数、跨帧混合 token 比例、每个 token 覆盖的时间跨度，以及补帧与真实历史帧的区分。
L **固定案例启动器。**按预先冻结的案例清单运行指定的任务与局次，输出明确标记为案例集，不会与正式结果混淆。

P 其中“每帧分到多少 token”需要先有定义：跨帧池化的一个输出 token 由多帧共同构成，因此我们采用按 patch 计数的分数归属，各帧贡献之和等于实际使用的 token 数。该定义随结论一同给出。

H2 4.2 主结果

P 表 1-1 给出了三种方法在同一训练条件下的成功率。按事前登记的辅助口径（排除 task 1，该任务在固定子集中的覆盖率仅 4%）：G2 为 41.56%（187/450），G3 为 23.78%（107/450），差 −17.78 点。逐任务看，G3 在十个任务中有八个低于 G2；差距最大的是 task 2（−42 点）与 task 4（−30 点），而 task 3 上 G3 高出 20 点。

P 关于基线的绝对水平：G0 的 23.40% 与官方 checkpoint 在同一链路上的 48.2% 之间的差距，来自训练充分程度——同数据同路径下，官方的动作 token 准确率为 0.9958，本项目 G0 为 0.705；G0 的准确率曲线到最后 5 000 步仍以每千步 +0.0117 上升。三种方法处于同一训练预算下，因此组间比较成立；与文献绝对值并列时需说明这一条件。

H2 4.3 预算翻倍下的稳健性

P 为检验 L0 不只在某一训练预算下成立，我们在 50 000 步上重复了 G0 与 G2：31.8% 提高到 48.0%，差 16.2 点，z = 5.31，p = 1.1e-7，置信区间 [10.2, 22.2]，事前阈值为点估计不低于 10.7 点。G2 在 50 000 步上的 48.0% 与官方在同一链路上的 48.2% 相当，而本项目冻结了视觉主干、训练样本量约为官方的 1/53。

P 需要说明口径：16.2 点来自 50 000 步的 G2 与 G0，18.60 点来自 30 000 步的 G3 与 G2，两者训练预算不同；主结果表统一使用 30 000 步这一组。

H2 4.5 补帧条件下的池化算子改进

P 在分析历史长度不足的窗口时，我们定位到分箱实现中的一处边界条件：占用数估计与实际分配使用了两套不一致的时间边界，历史不足时非空箱数会超出预算，按箱排序截断后最新一帧可能被整帧丢弃。

P 在 CPU 上以 K = 8、stride = 16、N = 256、n_t = 2 复现：真实帧数为 2、3、4 时最新帧保留的 patch 数为 0/256，对应 episode 的第 16 至 63 步。帧独立方案不受影响，因为其输出 token 不跨帧。

P 据此实现了固定时间轴与分组轴的分箱模式，自由空间轴继续等量分箱。新模式在完整八帧情形以及帧独立分组上与原实现逐位一致，只改变历史不足时的行为，并保证 1 至 8 个有效帧下全部有效 patch 均被保留；该性质已写入回归测试。

P 随后从底座独立重训了采用新模式的 G3（30 000 步，29.92 小时，RTX 4090，峰值显存 18.99 GB）并做满量评测，得到表 1-1 中的 23.60%。这一结果表明该边界条件虽然真实存在，但不是跨帧联合池化与帧独立方案之间差距的主要成因；机制解释因此转入本阶段的分配诊断。

H2 4.6 统计口径与检验方法

P LIBERO 的 n = 500（50 个初始状态 × 10 个任务，确定性评测）是样本量上限。按实测不一致率反推，检出 1.78 点需要 n 约 8358，检出 3 点需要 n 约 4300。因此 L1 与 L3 记为“未能证实”而非“证伪”，这一条件应与结论同时给出。

P 配对分析方面：G3 与 G4 的逐局不一致对为 152/450 = 33.8%，配对标准误为 2.74，非配对为 2.98。两种方法在三分之一的局上给出不同结果，逐局近似独立，因此配对带来的灵敏度提升有限。分析脚本逐对输出配对标准误，使该信息始终可见。

H1 五、当前结论与适用范围

P **成果表述：**在现有实验条件下，帧独立多帧方案优于单帧基线；跨帧联合池化未获得进一步收益，与单帧基线基本持平。项目据此以帧独立方案推进软件交付，并通过分配诊断与最小演示解释该工程边界。

H2 6.4 决策门

P 阶段 D 完成后作一次判断，三种结果各自对应的动作已写定：

L **若证据支持跨帧混合稀释了当前观测**：提出一个受限改版——为当前帧预留独立 token 配额，其余预算分配给历史，并保留帧身份。先完成设计、单元测试与离线分配对照，训练资源另行申请。
L **若固定案例没有一致的机制信号**：停止方法扩展，记为当前证据下无法定位单一机制，进入材料收口。
L **若导出链路本身需要调整**：修正工具并重采同样的六局，不增加任务或 episode 数。

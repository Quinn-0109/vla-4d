## 0. 已冻结的事实与边界

以下结果已经完成，不因本清单中的小样本采集而更新：

| 方法 | 固定预算下的视觉处理 | LIBERO-10 正式结果 |
|---|---|---:|
| G0 | 单帧 | 117/500 = 23.40% |
| G2@30k | 8 帧分别池化，满历史时每帧 25 token（共 200） | 211/500 = 42.20% |
| 修正版 G3@30k | 8 帧进入全局跨帧池化 | 118/500 = 23.60% |

当前结论是：历史观测有用，但现有 G3 的全局跨帧平均池化没有保住 G2 的收益。G3 已达到事前停止条件，
因此本阶段**不再训练、不做 G0/G2/G3 的 500 局重评、不启动旧四臂实验**。

本阶段只回答两个问题：

1. G3 是否因为跨帧混合而稀释当前状态或丢失时间身份？
2. 能否把已有系统整理成一个可复现、可解释、可演示的结项成果？

小样本轨迹只能用于机制诊断和演示，不能更新成功率、计算总体置信区间或宣称方法优劣。
历史 G0/G2 没有与 G3 等价的 500 条逐局记录，因此不得把少量补采数据送入完整 McNemar 配对检验。

### B2. 记录池化 token 的来源分配

`alloc_stats` 需要记录贡献关系，而不是只记录输出 token 数。每一步至少可推出：

- 每个输出 token 的来源帧编号、贡献 patch 数和权重；
- 最新帧贡献质量；
- 只由最新帧贡献的 token 数；
- 同时混合多个帧的 token 比例；
- 每个 token 覆盖的时间跨度；
- 每个输入帧对最终 token 的贡献质量；
- padding 帧与真实历史帧的区分。

如果池化是均值，最新帧“出现过”不能算作完整保留；诊断必须能量化它被多少旧帧稀释。

## D. 离线诊断与最小演示

### D1. 诊断表

按 arm、task、episode、成功/失败汇总：

- 最新帧贡献质量；
- 最新帧独占 token 数；
- 跨帧混合 token 比例；
- token 平均和最大时间跨度；
- 每一帧的贡献质量；
- 动作差异、夹爪翻转和完成步数。

同时提供逐案例数据，不对六局小样本做总体显著性结论。重点检查两个方向：

1. G3 失败时是否比 G3 成功时出现更强的跨帧混合或最新帧稀释；
2. 同一初始状态下，G2 保留的时间身份是否对应更稳定的动作。

表的主指标是**最新帧纯度**（只在含最新帧的 token 上，最新帧 patch 所占比例的平均）与
**最新帧所在 token 数**，两者乘积是最新帧份额。导出里原有的“全槽平均权重”把“分到的 token 少”
和“被旧帧稀释”混在一起——10-08 实测满历史时，G2 最新帧独占 25 个 token、纯度 1.0，全槽平均 25/200 = 0.125；
G3 最新帧分散在 121 个 token 里、纯度 0.25，全槽平均 30.25/242 = 0.125——数值相同，机制完全不同——
所以它只保留在 CSV 里，不单独用于判读。

### 本轮发现（详见 `docs/05` §13.14）

1. **G3 的分配结构是确定的**：满历史时每个输出 token 都是四帧平均、跨 48 个环境步，
   最新帧纯度 0.25、没有一个只属于最新帧的 token；G2 每帧 25 个纯 token。网格方法的分配
   只由真实帧数决定、与画面无关，所以“G3 失败局是否比成功局混合更多”用分配统计回答不了。
2. **G2 用的 token 最少**：满历史时 200 个，少于 G3 的 242 和 G0 的 256，成功率却最高。
   “每帧 32 token”的旧说法已在 README、`docs/05`、本清单中更正为 25。

   没有 G3 成功局。演示改用“同一初始状态下 G2（及 G0）成功、G3 失败”的案例。

# 受限改版设计：G3Q（最新帧独立配额）

日期：2026-10-08。来源：`docs/09` E 决策门选择第一支（受限改版：设计、单元测试、离线分配对照；
训练另设审查点）。机制依据见 `docs/05` §13.14。

## 1. 要回答的问题

同一训练条件下 G3（跨帧联合池化）比 G2（帧独立池化）低 18.60 点，并与单帧基线 G0 持平。
固定案例诊断确认了两件确定的事实：

- 满历史时 G3 的每个输出 token 都是四帧平均、跨 48 个环境步，**最新帧纯度 0.25、没有一个独占 token**；
  G2 每帧保留 25 个纯 token。
- G3 的 token 并不比 G2 少（242 对 200），“token 不够”这一解释已被排除。

诊断数据回答不了的是：**最新帧被旧帧稀释，是不是 18.60 点差距的主因**。网格方法的分配与画面无关，
只能用一次训练干预来检验。G3Q 就是为这个检验设计的。

## 2. 设计：相对 G3 只改一件事

| | G2 | G3 | **G3Q** |
|---|---|---|---|
| 最新真实帧 | 单独池化，预算 N ÷ 真实帧数 | 与旧帧混进同一批 token | **单独池化，预算 N ÷ 真实帧数（与 G2 逐位相同）** |
| 其余历史帧 | 每帧单独池化 | 跨帧联合池化（n_t=2） | **跨帧联合池化（与 G3 同一算子、同一 n_t）**，共享剩余预算 |
| 位置编码 | (t,h,w)，3 轴 | (t,h,w)，3 轴 | (t,h,w)，3 轴 |
| token 顺序 | 按 t̄ 升序 | 按 t̄ 升序 | 历史在前、最新帧在后，整体仍按 t̄ 升序 |

规则：真实帧数为 R 时，最新帧的预算为 `N // R`（R=8 时 32，实际 5×5=25 个 token），
历史帧共享 `N − N // R`。这样最新帧在每个历史长度上得到的 token **与 G2 给每一帧的完全相同**，
而历史帧的处理与 G3 相同。于是：

- **G3Q 对 G3**：只差“最新帧是否被稀释”；
- **G3Q 对 G2**：只差“历史帧是否跨帧混合、时间是否被抹平”。

两种结局都有信息量，不存在“只有正结果才有意义”的问题。

## 3. 离线分配对照（满历史，真实帧 8）

完整的 1–8 帧表见 `results/tables/allocation_g2_g3_g3q.md`（`python scripts/compare_allocation.py`
生成，G2、G3 两行与 10-08 真实诊断逐项一致）。

| | G2 | G3 | G3Q |
|---|---:|---:|---:|
| 使用 token | 200 | 242 | 225 |
| 最新帧所在 token | 25 | 121 | 25 |
| 最新帧纯度 | 1.00 | 0.25 | **1.00** |
| 最新帧独占 token | 25 | 0 | **25** |
| 跨帧混合 token 占比 | 0% | 100% | 89%（全部来自历史帧） |
| token 平均时间跨度 | 0 | 48 步 | 35.6 步（最新帧 0，历史 40） |

历史未满时同理：G3Q 的最新帧在每个 R 上都与 G2 相同（256、121、81、64、49、36、36、25 个，纯度 1.0），
历史帧从 R=3 起开始混合。

## 4. 已实现与验证（无 GPU）

- `pooling.wire`：新增方法 `G3Q`，`_pool_current_quota` 用 G2 的帧独立分组池化最新帧、用 G3 的
  跨帧联合池化处理历史帧，再把两段拼成 N 个槽；不与 `enforce_n` 同用。启动校验已放行 G3Q。
- 测试（`tests/test_g3q.py`）：
  - 每个历史长度上，G3Q 最新帧的 token 与 G2 的最新帧 token **逐位相同**，且不含任何旧帧 patch；
  - 历史帧之间仍有跨帧混合；
  - 每个有效 patch 恰好分配一次、补帧从不分配、已用槽连续在前、仍按 t̄ 升序；
  - 一个批次里各样本历史长度不同时，结果与逐样本计算一致；
  - 接线自检的八臂 PE 轴数对拍包含 G3Q。
- 训练与评测入口无需改动：G3Q 不属于 2×2，与 G2、G3-fixed 一样用全量数据训练。

### 事前判据（草案，审查时冻结）

主口径为 10 任务成功率（n=500，b8），9 任务口径同时报告。参照：G3 23.60%，G2 42.20%，差 18.60 点。
定义恢复比例 ρ = (G3Q − G3) / (G2 − G3)。

| G3Q 成功率 | ρ | 读法 |
|---|---|---|
| ≥ 36.0% | ≥ 2/3 | 最新帧被稀释可以解释差距的大部分 |
| 29.8%–36.0% | 1/3–2/3 | 部分解释；历史帧的跨帧混合同样有代价 |
| ≤ 29.8% | ≤ 1/3 | 最新帧被稀释不是主因；剩余嫌疑在历史帧的跨帧混合与时间抹平 |
| > 48.2% | — | 超过帧独立参照 6 点以上；记为正结果，但需另行确认，不在本轮扩展 |

G3 有逐局记录，G3Q 也会有，二者可做同一初始状态上的配对检验；报告时连同配对区间一起给出。
相邻区间的边界相距约 6 点，约为两倍标准误，落在边界附近时如实写“边界附近”，不强行归类。

## 6. 边界

- 一个训练种子、n=500 的硬上限，与此前各组相同。
- G3Q 的 token 数（225）介于 G2（200）与 G3（242）之间；它对 G3 的比较里 token 更少，
  对 G2 的比较里 token 更多。若 G3Q 接近 G2，token 数不能解释这一点；若 G3Q 接近 G3，
  G3Q 的 token 也并不更少。
- 逐局成败不随评测批量保持（`docs/05` §13.14 ④），所以正式判读只用 b8 的 500 局。
- 这是对一个机制假设的检验，不是为追求正结果而叠加模块；无论结果如何，主线交付仍是 G2。
